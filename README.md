# Discord 本地归档与答疑整理

在 Mac 或 Linux 上保存自己有权访问的 Discord 频道，并围绕指定答疑人生成文字稿和长图。数据与整理均在本机进行；基础功能不需要 Codex，也不需要安装语音模型。

第一次使用，先完成一个频道的“保存 → 出稿 → 下载图片”，确认可用后再添加其他频道或开启定时出稿。

## 需要拿哪些文件

当前修正版包含 **v0.4 首次连接扩展、连接协议 2、页面加载期间的按钮保护**。文件名保持下表所示；同一交付目录的 `CHECKSUMS.sha256` 用于核对原始 ZIP。实测范围与限制以 [当前修正版验收](docs/FINAL_PACKAGE_ACCEPTANCE.md) 为准，旧记录只保留历史过程。

| 你要做什么 | 拿哪些文件 | 放在哪里、从哪开始 |
| --- | --- | --- |
| Apple Silicon Mac 本地运行完整项目 | **只拿 `DiscordArchive-source.zip`**；已内嵌 Mac 首次连接工具 | 在 Mac 固定目录完整解压，先双击 `Install.command`；以后用 `Start.command` / `Discord Archive.app` |
| 首次部署 Ubuntu，访问端是 Mac | `DiscordArchive-source.zip` + `login-assistant-mac.zip` | 源码 ZIP 在 Ubuntu 安装；Mac ZIP 在访问电脑解压、首次连接和日常访问。服务器也可直接发布源码包内的 `helpers/login-assistant-mac.zip` |
| 首次部署 Ubuntu，访问端是 Windows | `DiscordArchive-source.zip` + `login-assistant-windows.zip` | 源码 ZIP 在 Ubuntu 安装；Windows ZIP 在访问电脑解压。Windows x64 尚待实机验收 |
| 新 Mac 访问已经连好 Discord 的 Ubuntu | **只拿 `login-assistant-mac.zip`** | 登录获准的 Tailscale 身份，双击 `Ubuntu Workspace.app`；不用安装源码、语音模型或重新绑定 |
| 新 Windows 访问已经连好 Discord 的 Ubuntu | **只拿 `login-assistant-windows.zip`** | 登录获准的 Tailscale 身份，双击 `Ubuntu Workspace.exe`；不用安装完整项目 |
| 本人首次连接或连接失效后重连 | 对应连接包里的 **`Browser Extension`** 文件夹 | 首次加载一次；已有服务器连接时，换电脑访问不需要加载它 |

Ubuntu 的连接包按**访问电脑**选择，不按服务器选择；两种访问电脑都用时才需要两个包。只有运行完整项目的机器安装语音：Mac 本地运行就在 Mac 装；Ubuntu 运行就在 Ubuntu 装。

交付目录的原始连接 ZIP 用于服务器发布。**从工作台下载的同名包是当前工作台专用的**，附带地址或 Mac 资料库标识，只在访问电脑使用，不拿回服务器重新发布。Mac 本地连接工具要从 Mac 本机工作台下载；Ubuntu 连接工具要从自己的 Ubuntu 工作台下载，核对目标后再确认账号。

开发与验收生成物留在项目内：分发包在 `dist/`，验收产物在 `artifacts/`，说明在 `docs/`。不额外往下载目录导出源码、客户端或测试文件。**只有需要本人手动加载或更新浏览器扩展时**，才把对应 `Browser Extension` 放到下载目录的固定文件夹；浏览器仍加载该目录时不要移动它。当前扩展 v0.4.0 本轮没有更新，无需重复导出。

**新电脑访问已有 Ubuntu，不需要重新绑定 Discord。** 账号连接、消息和模型都保存在服务器。新电脑只需登录同一个 Tailscale 账号，打开轻客户端即可；客户端可自动寻找同私网的工作台，找不到时才填一次可编辑的 HTTPS 地址。默认不安装扩展，不做网页配对，也不安装本项目、Node、Python 或语音模型。

Mac 本地完整项目模式保留；两份安装的数据和设置不自动同步。Ubuntu 的**首次 Discord 连接**与**换电脑访问**是两件事。新资料库先按下文做一次 [首次连接](#linux连接账号)：在日常浏览器正常登录 Discord，识别账号并确认交给自己的 Ubuntu。服务器已有连接时直接跳过；专用自动化登录窗口与旧版扩展退出默认路线。

## Mac 安装

1. 解压收到的 `DiscordArchive-source.zip`，保留完整的 **DiscordArchive** 文件夹，放到固定、可写的位置，例如个人文件夹内的“应用程序”（`~/Applications/DiscordArchive`）。不要只拖出里面的 App，后续也不要在服务运行时移动文件夹。
2. 双击文件夹里的 **Install.command**。它会打开终端窗口，检查并按需安装运行组件与浏览器。下载期间请保留窗口，等待完成。
3. 看到“**安装检查通过**”，随后浏览器自动打开“**工作台**”，才算安装和启动成功。页面拿到配置前，“保存一次 / 生成稿件”会保持禁用；按页面连接、配置频道后再操作。终端里若提示“安装未完成”，先按下方[故障处理](#遇到问题)处理。

若 macOS 阻止打开：先尝试双击，再到“系统设置 → 隐私与安全性”，按系统提示允许你信任的这份程序，之后重新打开。当前 App 没有 Developer ID 公证，不要关闭系统保护。

### Mac：连接账号

1. 打开 [Mac 本机工作台](http://127.0.0.1:8765)，点击 **首次连接 Discord**，下载 Mac 连接包并完整解压。首次安装器会自动发布随包提供的连接工具，不需要另外安装完整项目。
2. 双击包内 **首次连接 Discord.app**，按提示在日常 **Chrome / Edge** 加载一次 **Browser Extension**：Chrome 打开 `chrome://extensions/`（Edge：`edge://extensions/`），开启“开发者模式 → 加载已解压的扩展”，选择该文件夹。首次加载需本人完成；日常浏览器须已安装。
3. 在日常浏览器本人正常登录 Discord，回到 Discord 标签页点击扩展图标，点 **识别当前 Discord 账号**。核对目标是当前 Mac 的 `http://127.0.0.1:8765` 和正确账号，再点 **确认连接此账号**。工具会核对资料库身份，地址或资料库变更时拒绝提交。
4. 扩展提示“连接成功”，且工作台进入 **添加频道与答疑人**，才继续 [首次出稿](#第一次使用)。以后打开完整项目的 **Start.command / Discord Archive.app**，不重复加载或绑定。需要语音时按 [语音配置](#语音转写可选)安装。

此流程复用本人在日常浏览器完成的正常登录，不要求专用自动化浏览器通过验证码，不读取其他网站或聊天正文。原有账号连接仍保留，已经可用时不必重新连接。当前 Mac 分发包中的连接工具针对 Apple Silicon；Intel 需构建对应架构连接包，尚未实机验收。

**只部署 Ubuntu 的人直接从下节开始，不安装 Mac 完整项目，也不需要先做本节登录。**

## Linux 部署

以下用于 **Ubuntu 22.04 首次安装**；已有安装沿用原目录和资料，不另建实例。示例新目录为 `~/apps/DiscordArchive`。准备普通 SSH 账号、sudo、Python 3.10+、数 GiB 可用空间，以及收到的可信文件：

- `DiscordArchive-source.zip`：完整源码，只在 Ubuntu 安装。
- `login-assistant-mac.zip`：Apple Silicon Mac 连接工具与访问客户端，包含首次连接组件。
- `login-assistant-windows.zip`：Windows x64 连接工具与访问客户端（尚待实机验收）。只需准备实际使用的平台包；两平台都用时才准备两个。

可先通过 SSH/SFTP 上传源码 ZIP 和对应平台的连接包 ZIP 到服务器用户主目录；不需要在客户端安装完整项目。SSH 只用于服务器首次部署和维护，日常不用建立隧道。命令中的用户名、地址、端口和本地路径须替换；`scp` 的端口参数是大写 `-P`，`ssh` 为小写 `-p`。

### Linux：安装环境与后台服务

**在 Ubuntu 的 SSH 终端执行：**首次连接先通过可信途径核对服务器主机指纹。

```sh
python3 --version
df -h /
sudo apt-get update
sudo apt-get install -y unzip python3-venv
mkdir -p ~/apps
unzip -n ~/DiscordArchive-source.zip -d ~/apps
cd ~/apps/DiscordArchive
bash scripts/install_linux.sh --with-system-deps
```

Python 应为 3.10+。看到“**Linux 环境检查通过**”后继续：

```sh
sudo loginctl enable-linger "$USER"
python3 scripts/install_linux_service.py --install --no-autostart
python3 scripts/install_login_assistants.py --mac-zip ~/login-assistant-mac.zip
```

Mac 包已经内嵌在源码 ZIP 中：只上传源码时，可改用 `--mac-zip helpers/login-assistant-mac.zip` 发布；访问电脑仍拿单独 Mac ZIP，先由客户端打开工作台。上例发布 Mac 包；只用 Windows 时改为 `--windows-zip ~/login-assistant-windows.zip`，两者都用时同时传两个参数。发布器会拒绝缺少首次连接组件或协议版本不匹配的旧访问包。

确认 `ActiveState=active`、非零 `MainPID`。linger 让服务退出 SSH 后继续运行；`--no-autostart` 不开启下次开机自启动，以后在设置中自行选择。助手包先校验再发布，替换旧包时保留备份；不包含任何账号或模型。

需要语音时，仍在 **Ubuntu 项目目录**执行：

```sh
python3 scripts/install_speech.py
```

默认 **small 多语言模型、CPU / INT8**，无需独立 GPU。看到“**语音环境和模型已实际加载**”才继续；客户端不用安装模型。暂时跳过可在以后补装，详见 [语音配置](#语音转写可选)。

### Linux：启用 Tailscale HTTPS

服务器与访问电脑都按 [Tailscale 官方说明](https://tailscale.com/docs/install)安装客户端，并加入自己的私网。Ubuntu 安装方式见 [官方 Linux 安装说明](https://tailscale.com/docs/install/linux)。Tailscale 不由本项目自动注册账号。

**在 Ubuntu 执行：**

```sh
sudo tailscale up --hostname discordarchive-ubuntu
```

按终端给出的链接本人登录并批准这台服务器；保持命令等待到成功，已登录的服务器不必重复操作。然后在 **Ubuntu 项目目录**执行：

```sh
python3 scripts/configure_tailscale.py
sudo tailscale serve --bg http://127.0.0.1:8765
systemctl --user restart discordarchive.service
```

第一次使用 Serve 若出现启用 HTTPS 的网页链接，按提示由私网管理员确认，回终端等待完成；这可能是加入设备后另一轮确认，不要以为刚才登录失败。成功后执行 `tailscale serve status`，应显示实际 HTTPS 地址和 `127.0.0.1:8765` 转发目标；此时才继续。

配置器默认只允许该服务器注册时所属的 Tailscale 用户管理工作台；需要显式指定所有者时用 `--owner Tailscale登录名`。它会输出类似 `https://主机.私网.ts.net` 的固定地址，收藏自己的实际地址，别照抄别人的域名。

应用仍只监听 `127.0.0.1:8765`，由 Serve 提供私网 HTTPS；不开放公网，不启用 Funnel。工作台通过可信的 Serve 身份头识别获准管理员，不必再填工作台访问口令。其他用户、缺少身份头或公网转发均不获得管理权限。

### Linux：连接账号

**已有部署且工作台显示“已连接”时跳过此节。换电脑不会要求服务器重新登录 Discord。**

首次部署只做一次，使用 **Chrome / Edge 日常浏览器**，不在服务器上开 VNC，不在自动化窗口反复登录：

1. **先在访问电脑解压随部署包收到的对应客户端**，双击 **Ubuntu Workspace.app / Ubuntu Workspace.exe**，由专用直连窗口打开工作台；无预填地址时输入服务器配置器输出的 HTTPS 地址。不要先依赖普通浏览器打开 HTTPS 才去下载客户端，系统代理可能阻断这一步。进入工作台后也可用 **首次连接 Discord** 下载服务器专用包。Mac 双击包内 **首次连接 Discord.app**，Windows 双击 **Connect Discord.cmd**；它只安装当前用户的本机连接组件，不需要完整项目或模型。
2. 在 Chrome 打开 `chrome://extensions/`（Edge：`edge://extensions/`），开启 **开发者模式 → 加载已解压的扩展**，选择包内 **Browser Extension** 文件夹。当前扩展未上架，这个手动加载步骤只做一次。升级已加载的同目录扩展时点刷新，并按浏览器提示确认新增权限。
3. 在日常浏览器本人正常登录 [Discord](https://discord.com/channels/@me)，停在 Discord 标签页，点击扩展图标。新页显示目标服务器，点 **识别当前 Discord 账号**；它会刷新所选 Discord 标签页，识别后显示账号。核对服务器和账号，再点 **确认连接此账号**。
4. 只有页面提示 **连接成功**，并且 Ubuntu 工作台识别到账号，才算完成。自动任务保持暂停，先按 [首次出稿](#第一次使用)验证一个小频道。连接完成后，可关闭本机客户端或移除扩展，Ubuntu 独立采集；以后换电脑只需访问，不重复本节。

取消、超时和验证失败不会提交连接；服务器已有另一账号时不会直接覆盖。密码、验证码由本人在日常浏览器处理，不粘贴到工作台、终端或聊天里；工具不绕过 Discord 人机验证。浏览器无法正常登录 Discord 时，先处理浏览器的登录问题。

这是一条经本人确认的账号连接迁移流程，**不是 Discord 官方 OAuth**。普通 OAuth 的身份授权不等于频道历史读取权限；连接仍可能过期，届时重复本节即可。Mac 到空 Ubuntu 的首次连接与独立采集已实测；Windows 包已构建，尚待实机验收。详见 [首次连接验收与限制](docs/FIRST_LOGIN_ACCEPTANCE.md)。

### Linux：在新电脑打开工作台

1. 在新电脑安装并登录自己的 Tailscale，使用服务器获准的同一身份。
2. 完整解压对应访问客户端，Mac 双击 **Ubuntu Workspace.app**，Windows 双击 **Ubuntu Workspace.exe**。需要已安装 Chrome 或 Edge。
3. 客户端直接打开私网工作台，不弹配对页或 Discord 登录页。同私网中名称以 `discordarchive` 开头且属于本人管理的工作台可自动发现；只有找不到唯一服务器时才提示输入一次 HTTPS 地址。

**地址可以修改：**Mac 打开包内 **设置工作台.app**，Windows 打开 **设置工作台.cmd**，填写服务器实际 HTTPS 地址并保存。服务器专用下载包已预填地址。客户端只记住这个公开地址，不保存 Discord 登录连接，也不注册浏览器桥接组件。

工作台地址也可收藏在普通浏览器；系统代理有冲突时用轻客户端的专用直连窗口，不修改全局代理。约 3 MB 的客户端不需要项目运行环境或模型。当前 Mac 包为 Apple Silicon，Windows x64 尚待实机验收；Mac 仅本地签名，未 Developer ID 公证，首次只对可信包按系统提示允许打开。

## 第一次使用

以下步骤在已经打开的工作台中操作，Mac 和 Linux 共用。第一次先选一个频道完成出稿，再添加更多频道。

### 1. 确认连接与测试范围

确认 Mac 已按 [本机登录](#mac连接账号)完成连接，或 Ubuntu 已具备有效账号连接（[配置边界](#linux连接账号)）；在对应工作台看到“添加频道与答疑人”后继续。

先在 **高级设置 → 服务控制**选择“**暂停自动任务**”，再配置频道；首次部署建议保持暂停。暂停不影响手动保存、出稿和出图，避免首次配置后默认自动保存提前开始。

**只选一个历史消息与附件都少的频道。** 首次“保存一次”会读取这个频道全部仍可见的历史；“整个交易日 / 自选日期”只限制稿件范围，不限制采集量。当前工作台没有“只采 25 条”的开关，不能把验收脚本的限量取样当作产品功能。拿不准频道体量时，先不勾选大讨论频道。

### 2. 添加一个频道和答疑人

1. 按工作台提示点击 **添加频道与答疑人**，进入“频道与发言人”设置。
2. 在 Discord 中找到要保存的频道，右键其中一条消息，选“**复制消息链接**”。粘贴到“**频道 ID 或消息链接**”中。第一次先填一个频道；以后可每行填一个频道链接。
3. 找到你要整理的答疑人发过的一条消息，同样复制消息链接，粘贴到“**答疑人的一条消息链接**”。不需要自己查用户 ID。
4. 点击 **保存并返回工作台**。若是在“高级设置”中日常修改，则点击 **保存设置**，再回到工作台。

**检查：**“保存哪些频道”中应出现刚添加的频道，并勾选它。频道链接用于指定“保存哪里”，答疑人的消息链接用于指定“围绕谁整理”，两项都需要配置。

### 3. 保存消息并生成稿件

1. 点击 **保存一次**，等待正在处理的提示结束，并确认“**上次保存**”已更新。打开“**我的稿件 → 保存记录**”，确认这一轮保存成功；若显示失败或部分失败，先查看说明。
2. 点击左侧 **工作台** 返回；“生成稿件”按钮位于工作台，不在保存记录页。
3. 展开 **调整**，首次建议选择“**整个交易日**”，并在“**交易日期**”中选择一个你确认该答疑人发过消息的日期。这里按纽约时间凌晨 4 点划分交易日，不一定等于你电脑显示的自然日。
4. 点击 **生成稿件**，等待结果出现在“**最近稿件**”中。若提示所选范围没有目标发言，重新核对答疑人和交易日期。
5. 点击对应稿件的标题或 **打开 ↗**，查看文字是否包含预期的答疑内容。

**首次保存可能较久：**程序会读取该频道中仍可见的历史消息，耗时取决于内容量和网络。处理中先等待，不要反复启动程序。已经从 Discord 删除且从未保存的消息无法补回。

不调整时，默认整理范围是“最近一轮”：首次包含全部已保存的目标发言，后续主要选取相对上次成功保存新增或编辑的目标发言。需要整天或某段日期的内容时，展开工作台的 **调整**，选择“整个交易日”或“自选日期”；交易日按纽约时间凌晨 4 点分界。

### 4. 生成并下载第一张图片

1. 回到工作台，在“**最近稿件**”的对应条目旁点击 **生成图片**。首次可保持默认的“标准 · 1×”。
2. 等待图片生成完成，点击 **查看长图** 检查内容，再点击 **下载图片**。如果结果有多张，条目会显示“下载第 1 张”，其余图片可在长图预览中切换并下载。
3. 在浏览器的下载列表中找到 PNG，打开确认文字可读、内容符合预期。浏览器下载位置由浏览器设置决定。

**做到这里才算首次使用跑通：**保存记录成功、稿件有预期内容、下载的 PNG 能正常打开。只看到工作台或账号已连接，还不能证明保存和出图成功。

## 以后如何打开

| 运行方式 | 日常操作 |
| --- | --- |
| Mac 本地完整项目 | 双击 **Start.command** 或 **Discord Archive.app**，打开本机 `http://127.0.0.1:8765` |
| Ubuntu 服务器 | Tailscale 在线后打开自己收藏的 HTTPS 地址；使用代理时，双击轻客户端，直接由专用私网窗口访问 |

日常不需要手工建立 SSH 隧道、重复安装或重新绑定。没有安装完整 Mac 项目也能操作已有连接的 Ubuntu。客户端的专用工作台窗口绕过系统 HTTP 代理，不修改全局网络设置；默认不处理 Discord 登录。关闭客户端窗口即可退出，服务器已提交的任务与自动计划继续运行。

**Ubuntu 与 Mac 本地安装是两份资料。** HTTPS 地址操作服务器；`127.0.0.1:8765` 操作 Mac。Ubuntu 自动另存填写服务器绝对路径；浏览器下载仍到当前电脑的下载目录。

若服务器未开启自启动、主动停止过服务或重启后服务未运行，SSH 登录 Ubuntu，在任意目录执行：

```sh
systemctl --user start discordarchive.service
systemctl --user show discordarchive.service --property=ActiveState,MainPID
tailscale status
```

确认 active、非零 MainPID、Tailscale 在线后再打开 HTTPS 地址；原配置和数据保留。服务器开机自动运行可在 [自动启动设置](#自动启动可选)开启；[详细维护与旧版隧道](docs/LINUX.md)保留作诊断入口。不要通过开放公网端口解决访问问题。

## 日常操作

打开工作台后，勾选频道，依次完成“保存一次 → 生成稿件 → 生成图片 → 下载图片”；历史结果在“**我的稿件**”中查找。

**关闭网页、终端窗口或 App 后，已启动的采集服务仍可能继续运行。** Mac 睡眠、笔记本合盖或关机期间无法持续采集，也无法按时出稿。

需要控制后台运行时，打开 **高级设置 → 服务控制**：

- **暂停自动任务 / 恢复自动任务**：同时控制自动保存、断线重试和定时出稿；保留计划配置，暂停状态在服务重启后仍有效。网页、本地资料和手动保存、出稿仍可使用，已经开始的任务会完成。恢复后按原有补采、补稿规则处理到期任务。
- **重启服务**：等待已接受的任务结束后重启，页面自动重新连接；有未保存设置时须先保存。
- **更多操作 → 停止服务**：等待已接受的任务结束后退出，网页和手机访问随之断开；若由登录服务启动，同时停用自动拉起。Mac 再次打开 App 或 Start.command 可恢复启动，保留你选择的自动启动偏好；Linux 在服务器执行 `systemctl --user start discordarchive.service` 恢复。归档、稿件和凭证均保留。

手机可以暂停或恢复自动任务；重启和停止服务须在 Mac 本机页面，或通过本人 Tailscale HTTPS / SSH 隧道连接的 Linux 页面操作。已配对手机在服务重启后会自动恢复连接，无需刷新页面或重新输入口令，登录有效期保持 30 天。旧版内存中的登录记录无法迁移，本次升级后需重新登录一次；之后服务重启保持登录。


### 三种自动功能有什么区别

| 功能 | 做什么 | 如何设置 |
| --- | --- | --- |
| 自动保存 | 定期把消息保存到本机，不自动生成图片 | 高级设置 → 自动保存；默认启用 |
| 定时出稿 | 到点先保存消息，再生成稿件和图片，并另存到指定文件夹 | 高级设置 → 定时出稿；按下节启用 |
| 系统启动后自动运行 | 下次 Mac 登录或 Linux 开机后启动本应用 | 高级设置 → 自动启动；Linux 开机运行需一次性配置 linger |

首次手动保存与出图验收通过后，再决定是否在“服务控制”中恢复自动任务。服务开着但任务暂停时，计划不会执行。

自动保存默认每 6 小时一次，另在纽约时间周一至周五的 15:50—16:10 每 5 分钟保存一次；可在设置中调整。工作台显示“下次自动保存”。关闭“启用自动保存”并保存设置，可暂停这类定期采集；若还开启了“定时出稿”，它到点仍会先保存消息，需另行关闭。

### 定时出稿（可选）

1. 打开“高级设置 → 导出设置”：Mac 在“自动另存目录（Mac）”旁点 **选择文件夹**；Linux 点 **填写服务器目录**，填写服务器上的绝对路径。
2. 在“**定时出稿**”中填写出稿时刻，使用**纽约时间**；多个时刻用逗号分隔，例如 `10:45, 16:15`。
3. 选择执行日、版式、内容和清晰度；需要手机阅读版时，勾选“同时生成分栏图”。
4. 打开“**启用定时出稿**”，点击 **保存设置**，核对“**下次出稿**”显示的时间。
5. 到点后检查“最近状态”和另存文件夹，确认图片已生成。服务所在电脑须保持开机、联网且不睡眠，服务也须运行。

自动另存目录用于额外保存一份图片，不改变浏览器的下载位置。目录不可用时，稿件可能已生成但图片未另存，请查看页面错误。

计划自动跟随纽约夏令时；页面时间跟随当前手机或电脑。“周一至周五”不识别交易所节假日或提前收盘日。每次整理该纽约交易日的累计内容。

<details>
<summary>断线、重启与重复出稿规则</summary>

首次开启从当前分钟起生效；断线或重启后，在 48 小时内补最近一次到期计划，不逐次补旧时刻。同一时刻的成功结果不会重复生成；图片或目录失败会保留稿件并重试未完成阶段，无内容的交易日记为跳过。设置中可查看下次出稿时间和最近错误。

</details>

### 自动启动（可选）

在 **高级设置 → 自动启动** 直接选择，不需要每次执行终端命令：

- **Mac：登录后自动运行**。开启后在下次登录 Mac 时启动；关闭后不再自动启动，当前服务继续运行。
- **Linux：开机后自动运行**。已配置用户 linger 时在开机后启动；没有 linger 时页面会说明目前只能在登录后启动，管理员的一次性准备见 [Linux 后台设置](docs/LINUX.md#1-默认部署tailscale-https-与独立助手)。

开关直接保存到系统启动配置，不需要再点“保存设置”。页面应显示修改后的开关状态，不能只凭网页仍能打开认定已生效。关闭自动启动、暂停自动任务、停止服务是三个独立操作。

首次 Mac 安装默认不注册登录自启动；Linux 按部署手册先安装为手动运行。现有安装保留原系统状态。真正的开机/登录自启仍需在方便时重启系统或重新登录验收，不要在有任务时操作。

### 服务器关机与重启

Linux 的 **高级设置 → 服务器电源** 与“重启服务”分开：前者影响**整台服务器和其他程序**，后者只重启本应用。

电源操作仅允许通过服务器本机、本人 Tailscale HTTPS 或 SSH 隧道请求，需要输入“重启服务器”或“关闭服务器”确认，并等待本应用已接受的任务结束。没有系统授权时按钮禁用并显示原因；一次性管理员配置见 [Linux 服务器电源](docs/LINUX.md#6-服务器电源)。应用不保存 sudo 密码。

重启服务器后等待其上线且 Tailscale 恢复，再打开 HTTPS 地址；关机后需从主机或虚拟机管理工具开机，网页不能代替远程开机功能。

## 遇到问题

Mac 安装问题按下表处理；Linux 的 SSH、私网、隧道和服务问题见 [Linux 常见访问问题](docs/LINUX.md#4-常见访问问题)。

| 情况 | 先做什么 | 如何确认或继续处理 |
| --- | --- | --- |
| 安装或浏览器下载失败 | 保留终端最后的错误提示，检查网络后重新双击 Install.command | 等到“安装检查通过”；重新安装不会删除已有归档 |
| 工作台没有自动打开 | 在这台 Mac 的浏览器打开 [本地工作台](http://127.0.0.1:8765) | 仍打不开时，重新双击 Start.command，保留终端报错 |
| 需要重新检查环境 | 在项目目录执行 `./Install.command --check` | 根据输出处理缺失组件；检查不读取聊天或凭证 |
| 首次连接工具缺失或无法打开 | 重新取得包含首次连接工具的完整包，运行 Install.command，再从工作台下载连接包 | 新流程需日常 Chrome / Edge；导图仍用安装器下载的浏览器 |
| 无法连接 Discord 或保存失败 | 先确认日常浏览器能正常登录 Discord，再到“我的稿件 → 保存记录”看失败说明 | 认证失效时重新连接；权限失败时确认当前账号还能查看该频道 |
| 普通浏览器的 HTTPS 连接被关闭 | 双击访问客户端，由专用窗口直连工作台 | 不必修改系统代理；确认 Tailscale 在线、服务器 Serve 与应用运行；TUN / 企业强制代理另行诊断 |
| 账号连接失效或首次未连接 | 按 [首次连接](#linux连接账号)在日常浏览器识别账号并确认；已有资料保留 | 看到“连接成功”并用一个小频道验证；日常访问不重复绑定 |
| HTTPS 返回无权访问 | 核对客户端 Tailscale 登录身份是否是服务器配置的所有者 | 管理员在服务器检查 `data/remote-access.json`；不要改成接受任意身份头 |
| 语音安装失败或稿件没有转写 | 核对平台、FFmpeg、模型安装结果，以及目标发言人与稿件日期 | 模型应安装在实际运行应用的机器；修好后生成新稿件，不只重新打开旧稿件 |
| 使用代理，浏览器正常但保存失败 | 检查代理是否覆盖后台程序的连接，而不仅是浏览器；保留保存记录中的网络错误 | 当前 README 未提供适用于所有代理软件的配置步骤；求助时注明代理软件名称和启动方式，不要提供订阅链接或密钥 |
| 保存成功，但没有预期的答疑内容 | 核对频道、答疑人的消息链接和“调整”中的整理范围 | 目标发言需在已保存内容中；后续“最近一轮”可能没有新增发言，可改用“整个交易日”核对 |
| 文字稿有了，图片没生成 | 在稿件列表的对应条目旁点“生成图片”，查看是否有错误 | 环境检查失败时重跑安装；内容过大时缩小整理日期范围后再生成 |
| 定时出稿没有按时产生文件 | 检查“下次出稿”“最近状态”和页面错误，并确认服务所在电脑当时未睡眠 | 核对纽约时间、启用开关、服务是否运行及自动另存目录是否可用 |

Mac 工作台仍未就绪时，在 Finder 打开项目中的 `data` 文件夹，查看 `launcher.log` 或 `service.log`。Linux 使用 [服务状态与日志命令](docs/LINUX.md#5-日常管理与验收)。只提供与本次失败有关的错误片段。

**向别人求助时：**说明卡在哪一步、操作系统与芯片类型，以及当时的错误文字或截图。先遮住账号、频道、聊天内容和个人文件路径；不要发送密码、验证码、凭证、完整日志或整个 `data/` 文件夹。

## 语音转写（可选）

**在哪运行应用，就在哪里安装语音。** 访问客户端不处理账号或模型；只用 Linux 采集时，不必给客户端安装语音模型。

| 平台 | 在哪里操作 | 安装入口与默认配置 | 成功标志 |
| --- | --- | --- | --- |
| Apple Silicon Mac | Mac 的项目文件夹 | 双击 **Install-Speech.command**；MLX Medium 多语言模型 | “语音环境与模型检查通过”并最终显示“安装检查通过” |
| Ubuntu / Linux | 服务器 SSH 终端，先 `cd` 到服务器项目目录 | `python3 scripts/install_speech.py`；small 多语言模型、CPU / INT8 | “语音环境和模型已实际加载” |
| Intel Mac | 基础功能照常使用 | 当前语音安装入口不支持；需要语音时可部署到 Linux | 不将语音安装失败视为基础安装失败 |

安装需要联网下载环境与模型，并预留数 GiB 空间（尤其 Mac Medium）；转写在应用所在机器上读取本地模型和已保存音频。Mac 缺 FFmpeg 时，安装入口通过 Homebrew 按需安装。Linux 基础安装已准备 FFmpeg 和 Python venv。

Linux 模型位于 `.runtime/models/faster-whisper-small`，隔离环境位于 `.venv/whisper-linux`。默认不需要独立 GPU；NVIDIA CUDA 为可选配置，AMD 为后续适配方案，详见 [模型切换与 GPU 说明](docs/LINUX.md#3-语音转写默认-small--cpu)，不要把这些选项当成已完成 GPU 实机验收。

安装成功后**不用重启服务**：下一次“保存一次”或“生成稿件”会读取新配置，已开始的任务先等它结束，旧稿件不会自动更新。

### 如何确认语音真的能用

1. 先确认已保存的目标发言中确实有语音。若需要新采集，只选已知的小频道；不要为测试语音勾选整个大讨论频道。
2. 在工作台“调整”中选择这条语音所在的交易日或日期范围，点 **生成稿件**。语音应由指定答疑人发送；别人的语音未必被选进稿件。交易日按纽约时间凌晨 4 点分界。
3. 打开新稿件，确认出现“**语音转写**”，对照原音频核对内容，再点 **生成图片**、下载 PNG，确认转写文字也进入图片。
4. 若显示待转写或错误，按原因处理环境、模型或音频，再重新生成稿件；安装检查通过不等于实际语音已经转写成功。

未安装语音时仍保存原音频，基础文字和长图可用。转写是派生文字，尤其数字与交易术语需要回听核对。

已在 Ubuntu small / CPU 上完成真实短语音样本的下载、转写、缓存、文字稿、横版和手机版出图；另有小频道真实采集验收。范围与未验证项见 [Linux 验收记录](docs/LINUX_ACCEPTANCE.md)。限量样本通过不代表工作台支持限量采集，也不代表所有长语音或账号均已验收。

## 分享与隐私

**不要直接压缩自己的项目文件夹。** Mac 本地模式分享重新构建的 `DiscordArchive-source.zip`；Ubuntu 部署另提供访问电脑对应的连接包 ZIP；两种访问电脑都用时才提供两个。普通访问端只拿对应客户端包。

在 Mac 的项目目录执行：

```sh
PATH="$PWD/.runtime/bin:$PATH" python3 scripts/package_app.py
```

新版本生成在 `dist/` 下的新版本目录，不会覆盖旧包。独立助手的构建与校验见 [助手说明](docs/LOGIN_ASSISTANT.md)。分发包不含 `data/`、`output/`、登录浏览器资料、凭证、聊天、模型或本机依赖。接收完整项目的新部署需要安装依赖、连接自己的账号并添加频道；只访问已有 Ubuntu 的人不重装项目、不重复授权。迁移自己的历史数据请另看[迁移说明](docs/REFERENCE.md#换到另一台-mac)。

只使用本人已有的频道访问权限。普通成员账号自动读取存在 Discord 账号处罚风险；此工具不负责自动发布，也不向外部模型发送群聊。
