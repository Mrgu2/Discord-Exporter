# Discord 本地归档与答疑整理

给自己有权查看的指定频道做本地留存，并按群主的发言连接原问题、追问和补充。目标是常开 Mac 定时保存、随时手动保存，随后从本地记录生成这一轮或一段时间的文字稿。

保存与整理分开：保存尽量保留完整频道对话，整理时再按发言人筛选。否则只保存群主的回答，会丢掉别人提出的问题。

## 启动

在这份 README 所在目录运行：

```sh
python3 app.py
```

然后在常开 Mac 打开 <http://127.0.0.1:8765>。默认服务监听本机与局域网地址，供同一 Wi-Fi 的手机遥控。Mac 本机可直接使用；手机输入本机页面显示的独立访问口令后，才能读取资料和执行任务。不要将口令发给其他人。

在手机浏览器打开本机页面提供的 `.local` 或局域网 IP 地址，即可保存一轮、生成稿件和查看结果。同一 Wi-Fi 不需要 Tailscale。当前不开放公网端口，也未配置跨网络访问；需要外出使用时另行配置私有网络访问，不做路由器端口映射。

配置、归档与附件放在项目的 `data/` 目录，成稿与长图放在 `output/`，两个目录均以私有权限保存。账号凭证和本机文件导入只允许在 Mac 本机配置，不能从手机端修改或导入。

正常上手只需三步：

1. 在 Mac 页面点击“连接 Discord”，在打开的专用 Chrome 窗口正常登录或扫码一次。程序验证账号后保存连接，无需手抄密钥；不读取日常 Chrome 的其他网站或配置目录。
2. 勾选频道名称，点“保存一次”。当前项目已预配用户指定的五个频道；群主身份优先从用户提供的发言链接识别。
3. 点“生成稿件”得到文字与网页；默认版式为“上下分区拼图”：上方排主题栏目，下方排问答，同宽纵向合成一张。需要图片时点“生成图片”，完成后用“查看长图”或“分栏图”预览、缩放和下载。

分区图最多四栏，内容增加时向下延伸。长栏目可在下一栏继续，提问和回答整组保留；字号与原图比例不变。原“横向无缝长图”仍可选。单图最多 32000 像素宽/高、8000 万像素，超过时需缩小日期范围。

首次登录仍须本人完成；程序不代填密码、验证码或接受协议。登录窗口取消、超时或验证失败时，不会覆盖已有凭证。仅在自动连接不可用时使用“高级设置”中的手动连接。已有 DiscordChatExporter JSON 也可作为历史数据导入；能导入文件不代表实时采集权限已通过验证。

运行本地故障注入与回归检查：

```sh
python3 -m unittest discover -s tests -v
```

这些检查使用虚构消息和模拟网络响应，不读取真实 Discord 凭证，也不向 Discord 发请求。

运行跨模块验收（独立临时数据目录，虚构 Discord 响应，真实 HTTP 与图片渲染）：

```sh
python3 scripts/verify_workflow.py
```

该流程也验证定时时钟进入采集队列、失败游标保持不变，以及正常 30 秒退避后由同一工作线程自动重连，约需一分钟。账号、消息和失败响应均为虚构；不修改系统时钟，不切断本机网络。

当前本机验证结果及设备待办见 [验收记录](docs/ACCEPTANCE.md)。

## macOS 后台服务

先在前台确认页面与手动保存可用，再结束前台进程，安装后台服务：

```sh
python3 scripts/install_service.py --print
python3 scripts/install_service.py --install
python3 scripts/install_service.py --status
```

`--print` 只显示配置。安装使用当前用户的 LaunchAgent `local.discord.answer-archive`，登录后自启动、进程退出后自动重启；启动失败至少间隔 10 秒再试。Python 和工具路径写为绝对路径，长图渲染所需的 Node 路径单独写入运行环境。它不复制终端里的 Discord Token 或其他密钥；后台运行请使用本机凭证设置。

如果已有同名 plist，先按时间戳备份到 `data/service-backups/` 再更新。日志在 `data/service.log`；状态命令只显示运行状态和必要字段，不输出服务完整环境变量。状态里的 `loaded` 只表示已注册，还需核对进程是否运行，以及 <http://127.0.0.1:8765/api/health> 是否返回正常。真实采集成功仍以页面中的成功记录为准。

暂停并停用后台服务时执行：

```sh
python3 scripts/install_service.py --uninstall
```

这个命令停止并停用服务，保留 plist、备份、日志、凭证、归档与成稿。再次 `--install` 可以启用。它不会修改系统睡眠、电源或来电自动开机设置。

安装、启动与真实验收分开：LaunchAgent 必须在该 Mac 的用户登录后才能运行。放在“下载”等受系统隐私控制的目录时，macOS 可能要求允许后台进程访问文件；若健康检查失败，应检查系统权限与服务日志，不能仅凭 plist 写入成功判定安装完成。

## 换到另一台 Mac

1. 先等当前任务结束，在原 Mac 运行 `--uninstall` 停止后台服务。原目录保留，不删除。
2. 复制完整项目目录，包括私有的 `data/` 与 `output/`。数据库运行时不要单独复制一个 SQLite 文件；停止服务后复制完整数据目录。
3. 在新 Mac 前台运行并检查页面。macOS 钥匙串不会随目录复制，需要在新 Mac 页面重新连接 Discord。确认真实保存与文字稿可用；生成长图还需要该 Mac 的 Node.js、Playwright 与 Chromium/Chrome 运行环境。
4. 在新 Mac 重新运行 `--install` 和 `--status`，生成属于这台 Mac 的路径与登录服务。不要直接复制原 Mac 的 LaunchAgent plist。
5. 手机改用新 Mac 页面显示的访问地址，再核对一次保存和出稿。

两台 Mac 可以各自持有归档副本，但不要让它们同时写同一个数据库，也不要把正在写入的数据库放进同步盘来共享。常开采集职责由其中一台承担。

## 使用边界

- 仅访问明确配置的频道，使用账号已有的访问权限。
- 对 Discord 只执行读取操作；整理稿留在本机，发布到群里由你决定。
- 普通成员账号的自动访问存在 Discord 账号处罚风险。凭证等同于密码，不要发到聊天、提交到版本库或贴进日志。
- 归档只保留实际采集到的内容。原问题已被删除且从未保存时，稿件会标记上下文缺失，不能凭空补写。
- 图片和附件必须看下载状态；仅留有远端 URL 不代表已获得可离线使用的副本。
- 下载顶层附件、转发快照中的附件、Discord CDN 或图片代理上的嵌入图片与栅格贴纸；转发文字也保留。外部图片仅使用消息已有的 Discord 代理地址，不直接访问任意外站。SVG、Lottie 不内联；视频保留本地下载入口，长图不自动截取视频画面。

## 建议工作节奏

1. 常开 Mac 承担定时保存；两台 Mac 使用各自的数据目录，避免同时写入同一个数据库。
2. 开盘答疑结束，执行一次手动保存，再整理这一轮。
3. 尾盘补充结束，再保存一次；可单独整理这一轮，或合并当天时间范围。
4. 每周从已保存的数据生成一周合集。群里被清理后，已经保存在本地的记录仍可整理。

默认建议每 6 小时定时保存一次。手动保存和定时保存共用同一条采集路径，同一时间只允许一轮采集。每轮重复读取近期内容，用消息 ID 去重，并保留编辑版本。

## 文字稿与长图

保存后选择“最近一轮”“整个交易日”或自选日期范围出稿。默认生成“精简阅读”：问题出现一次，去掉重复的说明、逐条证据编号和可明确识别的客套闲聊，不改写交易条件、价格或短回答。没有“阅读提示”段落。每份结果同时保存 `archive.html`、`archive.md` 完整原文和 `evidence.json` 原文证据、筛选记录，不覆盖已经生成的稿件；也可在“调整”里直接选择“完整原文核对”。

“最近一轮”首轮整理全部已保存发言，后续只选相对上次成功保存新增或编辑的群主发言，避免尾盘稿重复上午内容。旧问题和旧回答仍可作为明确的回复上下文；失败的保存不作为比较基线。“整个交易日”和自选日期继续合并该范围内的完整发言。

精简阅读版按栏目顺序从左栏读到右栏，再接下一页；各页按完整问答块平衡两栏高度。完整原文版按实测高度比较双栏、主侧栏及问答块重排，选择留白较少的布局。原图保持比例，正文不缩小。也可选择四栏主题拼版 `board` 或问答单栏 `qa`。内容过多自动续页；每个主题另有手机版图片，能放在一页的问答不拆开。超出单页的长文按段续页。导出前检查来源消息、正文和静态图片是否均进入拼版；阅读版不逐条展示证据编号，完整 ID 保留在原文稿和证据文件中。

“横向无缝长图” `horizontal` 沿用固定列宽和 27px 正文，整组问答列满后向右延展，导出为一张连续 PNG。只有一个总标题，不重复分页页头、页脚或页码；普通列间距保留，图片等比。内容少的栏目可在同一列接续，内容多的栏目占用更多列。手机版仍另有分栏分页图。

超宽画布分成不超过 4096px 的片段渲染，再在本机按原像素无损合成为一张 PNG，不经 AI 或额外图像服务处理。这样避开本机 Chrome 在超宽一次截图中出现的右侧像素重复问题。片段校验和、接缝与末端像素另有 `node tests/png_check.mjs` 验证。

横向图以 32000px 宽、80MP 总面积作为产品保护值，超出时提示缩小日期范围，不缩字或静默截断。预览超宽图时默认按高度适配、定位最左，可缩放后横向拖动，也可点“适应屏幕”看全图。实体手机对大图的内存和相册兼容性仍需实测。

长图预览支持鼠标位置缩放、拖动、手机双指缩放、多页切换和下载，按 Esc 关闭后恢复原键盘焦点。系统启用“减少动态效果”时关闭入场动画。

长图需要 Node.js、Playwright，以及 Chromium 或本机 Chrome。当前机器可使用已经存在的运行环境；换到另一台 Mac 后要重新验证。若缺少 Playwright，可在项目目录安装：

```sh
npm install playwright
npx playwright install chromium
```

如果已经安装 Chrome，渲染器可直接使用它。也可通过 `PLAYWRIGHT_MODULE` 指定已有 Playwright 的 `index.js` 路径，或通过 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` 指定浏览器。后台服务不会自动继承终端临时设置的这些变量；使用项目内的 Playwright 安装最便于迁移和复验。

## 定时与时区

默认另外在纽约时间周一至周五的 15:50—16:10，每 5 分钟保存一次。可在设置中修改时间窗口、固定时刻和兜底间隔；固定时刻使用调度时区。这里的工作日规则不自动识别交易所节假日。

页面默认不需要选择时区：采集跟随美股交易时间，显示跟随当前手机或电脑；可选中国大陆、纽约、伦敦、东京作为固定显示地区。尾盘窗口用“收盘前几分钟、收盘后几分钟、每隔几分钟”设置。

程序内部用 `America/New_York` 的 IANA 规则跟随美国夏令时，记录保存 UTC。带电脑旅行或改变显示地区不会改变采集时刻。交易日以纽约凌晨 4 点分界；跨夏令时的一天可能是 23 或 25 小时，不按固定 24 小时截断。当前尾盘窗口以正常收盘时间为基准，交易所节假日和提前收盘日尚未自动识别；仍可手动保存，六小时兜底计划也独立运行。

首次采集读取频道中仍可见的历史；后续每轮至少回扫最近 48 小时。若上次成功更早，会向前补到上次成功时间之前 1 小时，直到读到边界或服务器已无历史。回扫用于补采与发现编辑，不能恢复此前已经删除的消息。历史轮次整理使用当轮保存的版本，后续编辑不会悄悄改写已经完成的开盘稿。

## 断网、断电与补采

网络临时中断时保留已经写入的内容；失败的一轮不推进成功游标。调度器自动重试，恢复后重新读取仍可见的消息并按 ID 合并。HTTP 429 遵守服务端等待时间；401 认证失败暂停并要求重新连接。单个频道 403 权限失效仅记录该频道失败，其他频道继续保存；全部频道拒绝访问时才暂停并提示处理权限。

每次请求的网络、服务端错误及短限流只做有限次重试，随后交给后台跨轮退避。较长的限流会直接进入等待，不能在服务端给出的 `Retry-After` 时间前再次请求。“距上次成功保存”表示采集覆盖的新鲜程度，不能用它认定网络已经连续断开了同样长的时间。

断电和关机期间程序无法运行。macOS 启动并登录后，后台服务才能接管、检查逾期任务并尝试补采。是否能在来电后自动开机取决于 Mac 型号和系统设置；FileVault 登录、网络登录页面和账号认证等步骤可能仍需本人完成。笔记本合盖或系统睡眠也会暂停采集，不能只凭后台服务已安装就认定全天在线。

如果频道约 48 小时清理一次，离线后能否补齐取决于恢复时消息是否仍存在。离线 10 小时通常还存在补采机会，但若离线横跨整批清理，即使时间更短也可能丢失。工具会提示可能的留存缺口，不会声称已恢复服务器上不存在的内容，也不会仅凭时间推断消息已经被删除。

## 结果核对

成稿应能沿消息 ID、时间与本地原文回查。整理过程中保留时间顺序、原话条件和后续修正；“上午判断”和“尾盘补充”不能被合并成一条无条件结论。缺失的引用、附件下载失败及可能超出清理窗口的离线时段需要保留提示。

正式投入使用前，至少完成一次小范围真实验收：指定一个频道和目标发言人，连续保存两轮、核对一条回复链，再在网络恢复后核对补采。单元测试能证明程序的故障处理，不等于证明账号、频道权限或真实网络已经可用。

## 本地隐私

归档数据库、生成稿件和附件可能包含群成员的私密内容。请放在自己控制的磁盘；迁移到另一台 Mac 时复制完整数据目录，并先停止源机器上的采集任务。不要把数据库放进两个进程同时写入的同步盘目录。

凭证配置在本机完成。诊断输出应只包含错误类别、状态和必要时间，不输出消息正文、请求 Authorization 头或完整凭证。当前工具不负责自动发帖，也不自动向外部模型发送群聊。

Discord 凭证优先写入当前用户的 macOS 钥匙串。钥匙串不可用时回退到 `data/credentials.json`，文件权限为 `0600`，页面会显示实际存储方式。环境变量 `DISCORD_ARCHIVE_TOKEN` 优先于本地保存值；若通过环境变量启动，更新页面里的凭证不会替换进程已继承的环境变量。

当前整理使用本地规则和明确回复关系，产出带出处的原文汇编，不向外部模型发送群聊。模型配置字段为预留，当前不能把它当作已支持的语义提炼功能。文稿仍需要你对照原文核对后决定是否发布。

## 可靠性验收覆盖

自动化检查使用虚构数据验证以下核心路径：

- 网络和服务端错误后恢复，持续错误的单次重试有上限；401 暂停，单个 403 不阻断其他频道。
- 429 同时支持响应正文和响应头中的等待时间。
- 分页中断后保留已写页且游标不前进；恢复后补齐并去重。
- 服务器重复返回同一页时停止；手动与定时采集互斥。
- 数据库重开后把中断任务标为失败，原文、编辑版本、轮次和游标仍可回查。
- 回复链缺失时标注缺失；只把邻近发言作为人工核对候选，不自动冒充原问题。
- 调度窗口去重、逾期补采、旅行显示时区、夏令时及交易日边界。

这与真实账号验收分开：必须在目标常开 Mac 上连接本人账号，完成真实保存，核对回复关系与图片，并实际观察断线恢复、登录后自启动及频道清理前后的留存。未做过的检查应继续标为待验收。
