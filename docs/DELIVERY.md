# 定时图片推送

将定时生成的原始 PNG 发到**邮箱、Telegram、Discord 或微信 ClawBot**，可多选，默认关闭。

先完成 [手动出图](USAGE.md#第一次采集出图)。用哪台机器出图，就在它的工作台配置推送；无需开放入站端口。

## 先选一个渠道

| 渠道 | 需要准备 | 适合什么用途 |
| --- | --- | --- |
| 邮箱 | SMTP 主机、端口、登录凭据、发件与收件邮箱 | 每日接收和保留原图，支持多个收件人 |
| Telegram | Bot Token、Chat ID；先向 Bot 发 `/start` | 私聊收图，也可配置群或频道 |
| Discord | 目标文字频道的 Webhook URL | 直接把图片发到自己的频道，无需另建完整 Bot |
| 微信 ClawBot | 手机有 ClawBot 入口，并能扫码确认 | 在个人微信收文件；会话失效时需要主动互动恢复 |

第一次只配一个常用渠道即可。希望长期无人值守时，建议保留邮箱或 Telegram；不要把微信 ClawBot 作为唯一收件方式。

## 从测试到每天自动收图

应用所在机器须开机、联网且不睡眠；恢复后的补跑规则见 [定时出稿](OPERATIONS.md#定时出稿可选)。

1. 打开 **高级设置 → 自动推送**，展开所选渠道，按下节配置。先保持渠道开关关闭。
2. 点击对应的 **保存并测试**。微信需要先扫码绑定并发一条消息，再点“保存并测试微信”。
3. 在下方发送记录中确认“已发送”，并到目标邮箱或聊天中确认测试附件确实收到。测试 PNG 很小，只检查发送连接，不代表真实长图或定时计划已经验收。
4. 打开需要的渠道开关，点击 **保存推送设置**。
5. 在 **定时出稿** 中设置时刻、执行日、版式、内容和清晰度，打开 **启用定时出稿**，点击 **保存设置**。首次建议选择标准 **1×**，避免大图超过附件限制。
6. 到 **服务控制** 检查自动任务是否暂停。若显示“自动任务已暂停”，点击 **恢复自动任务**，再核对“下次出稿”。
7. 第一次计划执行后，同时检查稿件图片、发送记录和收件端，确认整条流程跑通。

**保存推送设置**只管推送区；**保存设置**管频道、导出与定时出稿。**保存并测试**先保存推送区，再发送一次测试。

启用定时出稿前，配置另存目录或至少一个推送渠道。原图留在应用 `output/`；Docker 目录是容器内路径，原生版目录是该机器路径。浏览器下载位置另由浏览器设置。

普通手动生成图片不会自动推送。关闭某个推送渠道也不会关闭定时出稿；要停止计划，在定时出稿区关闭开关并保存，或暂停自动任务。

## 邮箱

在 **高级设置 → 自动推送 → 邮箱** 填写：

| 字段 | 怎么填 |
| --- | --- |
| SMTP 服务器 | 邮箱服务商提供的 SMTP 主机名，例如 `smtp.example.com`，不加 `https://` |
| 端口与连接加密 | 按服务商说明配套选择；SSL 通常为 465，STARTTLS 通常为 587 |
| SMTP 登录账号 | 服务商要求的登录名；留空使用发件邮箱 |
| 发件邮箱 | 实际发信邮箱，例如 `sender@example.com` |
| 收件邮箱 | 一个或多个地址，逗号分隔；最多 20 个 |
| SMTP 密码 / 授权码 | 按服务商要求使用 SMTP 授权凭据，未必是网页登录密码 |

部分邮箱需要先开启 SMTP 或创建应用专用密码；组织账号还可能受管理员策略限制。当前支持 SMTP 密码认证，**不支持 OAuth**，因此不是所有邮箱账号都能直接使用。

点击 **保存并测试邮箱**，在目标邮箱检查收件箱和垃圾邮件。记录中的“已发送”表示 SMTP 服务已接受提交，不能代替实际收件确认。多张图每张单独一封邮件。

## Telegram

### 1. 创建 Bot 并保存 Token

1. 在 Telegram 打开官方 [@BotFather](https://t.me/BotFather)，发送 `/newbot`，按提示设置显示名称和 Bot 用户名，取得 Token。
2. 打开新 Bot 的私聊，点 **Start** 或发送 `/start`。
3. 在应用 **Telegram** 设置中填入 **Bot Token**。先保持推送开关关闭，Chat ID 暂时留空，点 **保存推送设置**。

Token 只填入应用的密码框，不贴到聊天、截图或公开网页中。这里建议使用本应用专用的新 Bot，避免与其他程序争用消息更新。

### 2. 取得 Chat ID

在 **Docker 部署目录**执行下面代码，只读取已保存 Token 并显示 Chat ID，不发送消息。**Mac / 原生 Ubuntu** 在项目目录执行同段代码，将首行改为 `python3 - <<'PY'`。

<details>
<summary>展开 Chat ID 查询代码</summary>

```sh
sudo docker compose exec -T app python - <<'PY'
import json
import urllib.error
import urllib.request
from pathlib import Path
from discord_archive.settings import Credentials

if not Path('app.py').is_file():
    raise SystemExit('请先进入包含 app.py 的项目目录')
token = Credentials(Path.cwd()).get('delivery_telegram')
if not token:
    raise SystemExit('请先在 Telegram 设置中保存 Bot Token')
request = urllib.request.Request(
    'https://api.telegram.org/bot' + token + '/getUpdates',
    data=json.dumps({'timeout': 0, 'allowed_updates': ['message']}).encode(),
    headers={'Content-Type': 'application/json'},
)
try:
    with urllib.request.urlopen(request, timeout=20) as response:
        result = json.load(response)
except urllib.error.HTTPError as error:
    code = error.code
    error.close()
    raise SystemExit(f'Telegram 请求失败（HTTP {code}），请检查 Token 或 Bot 是否被其他程序占用') from None
except (OSError, ValueError):
    raise SystemExit('连接未完成，请检查运行应用这台机器的网络') from None
if not isinstance(result, dict) or not result.get('ok'):
    raise SystemExit('Telegram 未返回成功结果，请检查 Bot 配置')
chats = {}
for update in result.get('result', []):
    chat = (update.get('message') or {}).get('chat') or {}
    if 'id' in chat:
        chats[chat['id']] = chat.get('type', '')
if not chats:
    raise SystemExit('尚无聊天记录；请向新 Bot 发送 /start 后再执行')
for identity, kind in chats.items():
    print(f'Chat ID: {identity}  类型: {kind}')
PY
```

</details>

将 `private` 对应的数字填入 **Chat ID 或频道用户名**，点击 **保存并测试Telegram**，在自己的 Bot 私聊中确认收到附件。若出现多个 Chat ID，先核对目标聊天，不要猜一个发送。

使用群聊时，将 Bot 加入目标群并在群内向它发送 `/start@你的Bot用户名`，再读取该群的 Chat ID。公开频道可填写 `@频道用户名`，并给 Bot 发消息权限；私有频道需要准确的频道 ID。初次配置建议先把私聊跑通。[Telegram 官方入门](https://core.telegram.org/bots/tutorial#obtain-your-bot-token)

## Discord

1. 在你有“管理 Webhook”权限的服务器中，选一个接收图片的**文字频道**。
2. 打开 **编辑频道 → 整合（Integrations）→ Webhook**，创建 Webhook，确认目标频道，复制 URL。
3. 在应用 **Discord → Webhook URL** 中粘贴，点击 **保存并测试Discord**。
4. 到目标频道确认收到测试消息和 PNG 附件，再按需开启推送开关并保存。

只需要 Webhook，无需创建开发者应用或运行完整 Bot。当前只接受 `https://discord.com/api/webhooks/...` 地址，也支持路径带 API 版本号；不接收任意转发服务的 URL。Webhook URL 包含发送凭据，不要公开。发往频道的消息不会自动提及任何成员。[Discord 官方 Webhook 文档](https://docs.discord.com/developers/resources/webhook)

## 微信 ClawBot

手机微信需有 **我 → 设置 → 插件 → 微信 ClawBot** 入口。应用直接适配腾讯公开 iLink 协议，不要求安装或运行完整 OpenClaw。

1. 在应用展开 **微信 ClawBot**，点击 **扫码绑定微信**。此操作需通过本机、SSH 隧道或已配置的管理员连接进行。
2. 在手机的微信 ClawBot 页面点 **开始扫一扫**，扫描应用中的二维码，并在手机确认绑定。
3. 二维码最多保留五分钟。提示过期时点 **重新生成二维码**，扫描新码；旧码不能继续使用。若微信要求验证码，在应用里输入手机显示的验证码并提交。
4. 绑定成功后，在微信 ClawBot 对话中主动发一句“你好”。等待应用显示 **微信会话可发送**，再点 **保存并测试微信**。
5. 在手机确认收到 `test.png` 附件；之后按需开启推送开关，点 **保存推送设置**。绑定和测试都不会自动开启定时推送。

长图以原始 PNG **文件附件**发送，保留文件名。应用只使用扫码者的私聊消息更新会话，不保存消息正文，也不执行收到的文字。关闭自动推送会保留绑定，并继续接收会话更新；服务重启后自动恢复接收连接。

**微信定时发送有条件限制。** 长时间未互动后，微信可能拒绝发送，具体有效时间无法由本应用保证。出现“需微信操作”时，先在微信主动发一条新消息；会话恢复后，仍在重试范围内的记录会尝试补发。若提示登录失效，则重新扫码。若更换了账号或 Bot，旧队列不会静默转发到新账号，需确认收件人后手动重试。

建议保留邮箱或 Telegram 作为另一条收件渠道。微信“已发送”仍需结合手机实际收件判断。[腾讯 iLink 协议](https://github.com/Tencent/openclaw-weixin/blob/main/docs/protocol_zh_CN.md)、[官方仓库的定时推送问题记录](https://github.com/Tencent/openclaw-weixin/issues/309)

## 附件大小与多张图片

下表是**本应用当前使用的单文件检查阈值**，不是所有账号和服务商统一保证可接收的额度：

| 渠道 | 本应用单张检查阈值 | 发送方式 |
| --- | --- | --- |
| 邮箱 | 18 MiB | 每张一封邮件，原始 PNG 附件；双方邮箱仍可能有更小限制 |
| Telegram | 50 MiB | 文件附件；页码见消息说明 |
| Discord | 10 MiB | 频道消息附件；实际平台限制仍可能不同 |
| 微信 ClawBot | 18 MiB | 保留原文件名的文件消息 |

多页、同时选择标准与 HiDPI、或生成分栏图时，会有多份发送记录。平台界面可能把多条消息折叠或合并展示，需检查是否所有页都已收到。

超限时不会擅自压缩或删除图片。降低清晰度或缩小稿件日期范围后重新生成；已有失败记录仍指向旧图，单纯点“重试”不会把大图自动变小。

## 状态、重试与暂停

| 页面状态 | 含义与操作 |
| --- | --- |
| 等待发送 | 已入队；任务串行处理，可能在等待其他任务结束。主动测试和手动补发不受“暂停自动任务”影响 |
| 等待重试 | 发送失败，按页面时间自动重试；可先修正网络或配置 |
| 需微信操作 | 先在微信发一条消息，或按错误提示重新扫码；更换绑定后须确认目标再手动重试 |
| 发送失败 | 自动尝试已达到上限；处理错误后点“重试发送” |
| 已发送 | 平台已接受发送；第一次配置仍要到收件端确认附件收到且能打开 |

普通发送失败最多自动尝试 8 次，失败后间隔从 30 秒逐步增加，上限 30 分钟。微信需要人工恢复的会话错误会停下等待，不持续消耗重试次数。达到尝试上限后仍可手动重试。

队列和结果持久化，服务重启后继续处理；每个渠道、每张图片分别记录，其他文件失败不会让已成功文件跟着重发。设置显示最近 30 条记录，列表内部滚动。已完成的测试记录保留最近 100 条，正式发送成功记录保留最近 1000 条；只整理发送记录，不删除图片、稿件或采集原文。尚未完成的正式任务保留；待处理队列达到 1000 条时停止接收新记录并提示处理失败项。超出保留范围的成功记录不再提供历史去重，请勿重新提交旧稿件作为补发方式。

恢复后的补稿规则见 [断线与重启](OPERATIONS.md#定时出稿可选)。若收件端已收到，但应用在记录成功前中断，重试可能重复投递。

- **暂停自动任务**：暂停自动采集、定时出稿和自动推送；保留开关配置，重启后仍暂停。主动测试和手动补发继续执行，包括它们的失败重试。
- **关闭渠道**：暂停该渠道尚未完成的自动推送；重新开启后继续。主动测试或手动补发仍是明确的发送操作。
- **手动重试**：使用最新保存的目标配置。先修正邮箱或 Chat ID，再点击重试；更换目标意味着把该记录发给新的收件人。

自动重试使用入队时的目标和最新凭据；手动重试改用最新保存的目标。确认丢失或邮箱部分拒收时可能重复发送，不保证恰好一次。

目录另存失败时，原有定时出稿状态会显示错误，但已生成图片的远程发送可以继续。发送失败不会删除原始消息、稿件或图片。

## 已有安装如何更新

**Docker 更新先看 [Docker 数据与更新说明](DOCKER.md#日常管理与资料保存)，不要使用下列原生安装命令。**

以下用于 Mac / 原生 Ubuntu。更新服务端；仅更新访问客户端不会更新服务器。保留自己的资料，不导入他人凭据。

1. 等待当前任务结束，记下项目目录，备份现有 `data/`、`output/` 和自己的配置；含凭据的备份只由本人保管。
2. 停止本应用服务。将可信新源码合并到原项目目录，保留自己的 `data/`、`output/`、`.runtime/` 等本地资料，不要删除旧资料或直接覆盖为别人的资料库。
3. 重新安装锁定的项目依赖：Mac 运行 `./Install.command --no-open`；Linux 在项目目录运行 `bash scripts/install_linux.sh`。安装器会处理锁定依赖。
4. 确认安装检查通过，再按 [日常打开方法](OPERATIONS.md#以后如何打开)启动或打开工作台。若原服务仍在运行，从 **服务控制 → 重启服务** 加载新后端；已有未保存设置须先保存。
5. 刷新工作台，确认“自动推送”有四个渠道；每个使用中的渠道重新做一次测试，核对原计划和暂停状态。重新安装不会替你打开推送或恢复自动任务。

不熟悉源码合并时，先保留原目录和备份，按 [打包说明](PACKAGING.md)使用重新构建的新版本，不要自行清空归档。当前工作区源码已更新，不代表此前发出的 ZIP 已包含新功能。

## 网络、凭据与排错

服务器必须能访问相应平台的 HTTPS API 或邮箱 SMTP 服务。浏览器能访问平台，不等于后台进程能访问；使用代理、云服务器 SMTP 出站受限时，需检查应用所在机器的网络。不要用开放公网工作台端口来解决出站发送问题。

密码框留空表示保留已保存值；页面不会回显凭据。如果配置正确却仍用旧凭据，检查服务环境变量是否覆盖了页面保存值。支持的变量：`ARCHIVE_SMTP_PASSWORD`、`ARCHIVE_TELEGRAM_TOKEN`、`ARCHIVE_DISCORD_WEBHOOK`；ClawBot 的环境变量形式只适合维护人员，首次使用走扫码流程。

macOS 优先用系统钥匙串；系统钥匙串不可用或在 Linux 时，凭据存入权限 `0600` 的私有文件。队列在 `data/delivery-state.json`，ClawBot 会话在 `data/clawbot-state.json`；不要公开这些文件。二维码在本地生成，文件加密上传使用 Node.js 内置加密组件。

常见问题见 [推送故障排查](TROUBLESHOOTING.md#图片推送问题)。求助时只提供渠道名、错误文字、系统与运行位置，遮住 Token、Webhook、授权码、二维码和聊天内容。
