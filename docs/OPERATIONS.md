# 日常管理

## 以后如何打开

| 运行方式 | 日常访问 | 服务已停止时 |
| --- | --- | --- |
| Mac 本地 | 双击 **Start.command / Discord Archive.app**，使用实际启动地址 | 同左 |
| Ubuntu Docker | Tailscale 在线后，打开收藏的 HTTPS 地址 | SSH 进入部署目录，执行 `sudo bash Start-Docker.sh` |
| Ubuntu 原生 | 同上；代理冲突时用 [访问客户端](ACCESS.md) | SSH 执行 `systemctl --user start discordarchive.service` |

已有连接无需重绑，日常不用 SSH 隧道。关闭浏览器或访问客户端不停止服务器任务。

Mac 本地与 Ubuntu 各自保存资料。浏览器下载到当前电脑；自动另存使用应用所在机器的路径，Docker 使用容器内路径。

## 日常操作

在工作台依次完成 **保存一次 → 生成稿件 → 生成图片 → 下载图片**，历史结果在 **我的稿件**。

**高级设置 → 服务控制**提供：

| 操作 | 效果 |
| --- | --- |
| 暂停 / 恢复自动任务 | 控制自动保存、自动重试、定时出稿和自动推送；暂停状态在重启后保留 |
| 重启服务 | 等待已接受任务结束后重启，页面自动重连；先保存未提交的设置 |
| 更多操作 → 停止服务 | 等待任务结束后停止，网页随之断开；按上表恢复，资料保留 |

暂停期间，手动保存、出稿、测试发送和手动补发仍可执行，已开始任务会完成。关闭自动启动不会停止当前服务。

手机可暂停和恢复任务。重启、停止由 Mac 本机或获准的 Ubuntu 管理连接操作；已配对手机在服务重启后自动重连，登录有效期为 30 天。

### 自动功能与推送有什么区别

| 功能 | 做什么 | 设置位置 |
| --- | --- | --- |
| 自动保存 | 定期保存消息，不生成图片 | 高级设置 → 自动保存，默认启用 |
| 定时出稿 | 到点保存、生成稿件和图片 | 高级设置 → 定时出稿 |
| 自动推送 | 将定时图片发给指定收件人 | 高级设置 → 自动推送，默认关闭 |
| 自动启动 | 登录 Mac、启动 Ubuntu 或容器时运行应用 | 高级设置 → 自动启动 |

自动保存默认每 6 小时一次，并在纽约时间周一至周五 15:50—16:10 每 5 分钟执行。关闭自动保存后，已启用的定时出稿仍会到点采集；暂停自动任务可一起暂停。

### 定时出稿（可选）

1. 先配置自动另存目录，或按 [推送教程](DELIVERY.md)启用收图渠道。
2. 在 **定时出稿**设置纽约时间、执行日、版式、内容和清晰度；多个时刻用逗号分隔，如 `10:45, 16:15`。
3. 打开 **启用定时出稿**，点本区 **保存设置**。推送区另有 **保存推送设置**。
4. 在 **服务控制**恢复自动任务，核对“下次出稿”；首次执行后检查图片与实际收件。

服务须开机、联网且不睡眠。计划跟随纽约夏令时，页面时间跟随访问设备；工作日选项不识别交易所节假日或提前收盘日。

<details>
<summary>断线、重启与重复出稿规则</summary>

首次启用从当前分钟生效。恢复运行后先续作中断任务，再补最近 8 天内最后一次到期计划，不逐次补旧时刻。成功结果不重复生成；无内容的交易日跳过，失败保留已完成阶段供重试。

暂停状态会保留，需先恢复自动任务。推送重试与重复投递的边界见 [发送状态](DELIVERY.md#状态重试与暂停)。

</details>

### 自动启动（可选）

在 **高级设置 → 自动启动**选择，开关直接保存：

- **Mac：登录后自动运行**，首次安装默认关闭。
- **Ubuntu Docker：容器启动后自动运行**，默认关闭；容器自身由 Docker 管理。详见 [Docker 管理](DOCKER.md#日常管理与资料保存)。
- **Ubuntu 原生：开机后自动运行**。需配置 linger，否则只能登录后启动，见 [原生安装](LINUX_SETUP.md#安装环境与后台服务)。

关闭开关不停止当前服务；暂停任务、停止服务、自启动是三个独立操作。开机或登录自启需在方便时实际验证，避免中断正在运行的任务。

### 服务器关机与重启

**Docker 版仅管理容器内应用，不提供主机关机或重启。**

原生 Ubuntu 的 **高级设置 → 服务器电源**影响整台服务器。需系统授权、输入操作确认文字，并等待当前任务结束；配置见 [服务器电源](LINUX.md#6-服务器电源)。关机后需从主机或虚拟机管理工具开机。

### 端口占用

应用自动尝试空闲端口，显示实际地址，不停止占用者。再次启动优先沿用上次端口；Mac 启动入口会核对资料库身份。

Ubuntu 端口变化后，检查 HTTPS 是否仍能打开：

- **Docker**：在部署目录执行 `sudo bash Configure-Tailscale.sh`，核对输出命令。
- **原生**：在项目目录执行 `python3 scripts/configure_tailscale.py`，按输出修正转发。只有原路由属于本项目且权限允许时，应用才自动同步。

已有其他 Serve 路由时先核对，不覆盖其他服务、不开放公网。
