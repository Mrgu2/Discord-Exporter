# 日常管理

## 以后如何打开

| 运行方式 | 日常操作 |
| --- | --- |
| Mac 本地完整项目 | 双击 **Start.command** 或 **Discord Archive.app**，打开本机 `http://127.0.0.1:8765` |
| Ubuntu 服务器 | Tailscale 在线后打开自己收藏的 HTTPS 地址；使用代理时，双击轻客户端，直接由专用私网窗口访问 |

日常不需要手工建立 SSH 隧道、重复安装或重新绑定。没有安装完整 Mac 项目也能操作已有连接的 Ubuntu。客户端的专用工作台窗口绕过系统 HTTP 代理，不修改全局网络设置；默认不处理 Discord 登录。关闭客户端窗口即可退出，服务器已提交的任务与自动计划继续运行。

**Ubuntu 与 Mac 本地安装是两份资料。** HTTPS 地址操作服务器；`127.0.0.1:8765` 操作 Mac。Ubuntu 自动另存填写服务器绝对路径；浏览器下载仍到当前电脑的下载目录。

若服务器未开启自启动、主动停止过服务或重启后服务未运行，SSH 登录 Ubuntu，在任意目录执行：

```sh
systemctl --user start discordarchive.service
systemctl --user show discordarchive.service --property=ActiveState,MainPID
tailscale status
```

确认 active、非零 MainPID、Tailscale 在线后再打开 HTTPS 地址；原配置和数据保留。服务器开机自动运行可在 [自动启动设置](OPERATIONS.md#自动启动可选)开启；[详细维护与旧版隧道](LINUX.md)保留作诊断入口。不要通过开放公网端口解决访问问题。

## 日常操作

打开工作台后，勾选频道，依次完成“保存一次 → 生成稿件 → 生成图片 → 下载图片”；历史结果在“**我的稿件**”中查找。

**关闭网页、终端窗口或 App 后，已启动的采集服务仍可能继续运行。** Mac 睡眠、笔记本合盖或关机期间无法持续采集，也无法按时出稿。

需要控制后台运行时，打开 **高级设置 → 服务控制**：

- **暂停自动任务 / 恢复自动任务**：同时控制自动保存、自动采集重试、定时出稿和自动推送；保留计划配置，暂停状态在服务重启后仍有效。网页、本地资料和手动保存、出稿仍可使用；主动测试发送和手动补发也会继续，已经开始的任务会完成。恢复后按原有补采、补稿规则处理到期任务。
- **重启服务**：等待已接受的任务结束后重启，页面自动重新连接；有未保存设置时须先保存。
- **更多操作 → 停止服务**：等待已接受的任务结束后退出，网页和手机访问随之断开；若由登录服务启动，同时停用自动拉起。Mac 再次打开 App 或 Start.command 可恢复启动，保留你选择的自动启动偏好；Linux 在服务器执行 `systemctl --user start discordarchive.service` 恢复。归档、稿件和凭证均保留。

手机可以暂停或恢复自动任务；重启和停止服务须在 Mac 本机页面，或通过本人 Tailscale HTTPS / SSH 隧道连接的 Linux 页面操作。已配对手机在服务重启后会自动恢复连接，无需刷新页面或重新输入口令，登录有效期保持 30 天。


### 自动功能与推送有什么区别

| 功能 | 做什么 | 如何设置 |
| --- | --- | --- |
| 自动保存 | 定期把消息保存到本机，不自动生成图片 | 高级设置 → 自动保存；默认启用 |
| 定时出稿 | 到点先保存消息，再生成稿件和图片；可另存目录或交给推送渠道 | 高级设置 → 定时出稿；按下节启用 |
| 自动推送 | 把定时生成的图片发到邮箱、Telegram、Discord 或微信 ClawBot | 高级设置 → 自动推送；默认关闭，先测试再启用 |
| 系统启动后自动运行 | 下次 Mac 登录或 Linux 开机后启动本应用 | 高级设置 → 自动启动；Linux 开机运行需一次性配置 linger |

首次手动保存与出图验收通过后，再决定是否在“服务控制”中恢复自动任务。服务开着但任务暂停时，计划不会执行。

自动保存默认每 6 小时一次，另在纽约时间周一至周五的 15:50—16:10 每 5 分钟保存一次；可在设置中调整。工作台显示“下次自动保存”。关闭“启用自动保存”并保存设置，可暂停这类定期采集；若还开启了“定时出稿”，它到点仍会先保存消息，需另行关闭。

### 定时出稿（可选）

1. 先选择收图方式：需要额外目录副本时，在 **导出设置** 中选择目录或填写 Linux 服务器绝对路径；只用远程推送时，先按 [推送教程](DELIVERY.md)配置并启用一个渠道，可以不填另存目录。
2. 在 **定时出稿** 中填写出稿时刻，使用 **纽约时间**；多个时刻用逗号分隔，例如 `10:45, 16:15`。
3. 选择执行日、版式、内容和清晰度。第一次建议标准 **1×**；需要手机阅读版时，勾选“同时生成分栏图”。多页、多个清晰度和分栏图会增加发送文件数。
4. 打开 **启用定时出稿**，点击本区的 **保存设置**。推送区使用另一个 **保存推送设置**，两者都要按修改范围保存。
5. 在 **服务控制** 确认自动任务没有暂停；若暂停，点击 **恢复自动任务**。核对“下次出稿”显示的时间，而不是“已暂停”。
6. 第一次到点后，核对“最近状态”、生成图片及所选目录或收件渠道。推送记录“已发送”之后，还需确认邮箱或聊天中确实有真实长图，并且能打开。

服务所在电脑须保持开机、联网且不睡眠。自动另存是额外的目录副本，不改变浏览器下载位置；原图仍在应用 `output/` 中。目录不可用时，原有出稿状态会显示错误，但已生成图片的远程推送可以继续；反过来，推送失败不会删除原图。

**测试发送不等于每天自动发送。** 需要同时满足：渠道已启用并保存、定时出稿已启用并保存、自动任务未暂停、服务正常运行。绑定 ClawBot 或测试渠道成功都不会替你打开这些开关。主动测试和手动补发在自动任务暂停时仍能执行。

计划自动跟随纽约夏令时；页面时间跟随当前手机或电脑。“周一至周五”不识别交易所节假日或提前收盘日。每次整理该纽约交易日的累计内容。

<details>
<summary>断线、重启与重复出稿规则</summary>

首次开启从当前分钟起生效；断线或重启后，补最近 8 天内最后一次到期计划，不逐次补旧时刻。同一时刻的成功结果不会重复生成；中断任务优先从已保存阶段恢复，包括采集、稿件和图片；图片或目录失败会保留稿件并重试未完成阶段，无内容的交易日记为跳过。设置中可查看下次出稿时间和最近错误。

### 自动启动（可选）

在 **高级设置 → 自动启动** 直接选择，不需要每次执行终端命令：

- **Mac：登录后自动运行**。开启后在下次登录 Mac 时启动；关闭后不再自动启动，当前服务继续运行。
- **Linux：开机后自动运行**。已配置用户 linger 时在开机后启动；没有 linger 时页面会说明目前只能在登录后启动，管理员的一次性准备见 [Linux 后台设置](LINUX.md#1-默认部署tailscale-https-与独立助手)。

开关直接保存到系统启动配置，不需要再点“保存设置”。页面应显示修改后的开关状态，不能只凭网页仍能打开认定已生效。关闭自动启动、暂停自动任务、停止服务是三个独立操作。

首次 Mac 安装默认不注册登录自启动；Linux 按部署手册先安装为手动运行。现有安装保留原系统状态。真正的开机/登录自启仍需在方便时重启系统或重新登录验收，不要在有任务时操作。

### 服务器关机与重启

Linux 的 **高级设置 → 服务器电源** 与“重启服务”分开：前者影响**整台服务器和其他程序**，后者只重启本应用。

电源操作仅允许通过服务器本机、本人 Tailscale HTTPS 或 SSH 隧道请求，需要输入“重启服务器”或“关闭服务器”确认，并等待本应用已接受的任务结束。没有系统授权时按钮禁用并显示原因；一次性管理员配置见 [Linux 服务器电源](LINUX.md#6-服务器电源)。应用不保存 sudo 密码。

重启服务器后等待其上线且 Tailscale 恢复，再打开 HTTPS 地址；关机后需从主机或虚拟机管理工具开机，网页不能代替远程开机功能。

### 端口占用

启动时若请求端口被其他程序占用，应用会尝试后续空闲端口，并在终端、工作台“手机访问”处显示实际端口；不会停止占用端口的程序。再次启动优先沿用上次选中的端口。Mac 的 App / Start.command 会读取当前资料库的地址，并核对项目身份，避免打开另一份项目。

Ubuntu 始终保留本机监听。已有 Tailscale Serve 根路径仍指向本项目旧端口、且当前用户有配置权限时，会同步到新端口；权限不足或发现其他转发配置时，会明确告警而不覆盖。通过 SSH 在项目目录运行 `python3 scripts/configure_tailscale.py`，执行它输出的管理员命令即可修正。此时本地应用已启动不等于 HTTPS 转发已恢复；请最后用 HTTPS 地址打开工作台确认。
