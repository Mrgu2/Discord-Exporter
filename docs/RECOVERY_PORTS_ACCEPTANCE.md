# 可操作性与恢复验收

本轮保留原归档、图片、登录连接和计划配置。测试在项目 `artifacts/task-recovery/` 与 Ubuntu 独立测试目录进行，没有向真实收件人发送测试消息，也没有重启电脑或服务器。

## 改动与检查

- README 保留功能介绍，安装教程和维护入口默认折叠；Mac 用源码包并直接登录，Ubuntu 用源码包部署、访问端使用对应客户端。85 个本地文档链接及锚点无断链。
- 暂停状态优先于过期的重试时刻；桌面 1360px、手机 390px 下连续跨越轮询和时钟更新检查，未再出现“已暂停／即将重试”交替覆盖。
- 手机访问增加 Tailscale 提示。Mac 局域网监听时可显示本机 Tailscale IP 地址；Ubuntu 默认本机监听，手机使用 HTTPS 域名，不能照抄 IP:8765。
- 推送列表显示最近 30 条并内部滚动。已完成测试记录保留 100 条、正式成功记录保留 1000 条；未完成正式任务不清理，待处理达到 1000 条拒绝继续积压。原图、稿件和原文不自动删除。已淘汰成功记录不再提供旧稿件去重。
- 软件恢复后，先按持久化检查点继续中断任务，再补最近 8 天内最后一次错过的出稿计划；不逐个补发所有旧时刻。暂停状态保持，需用户恢复。已确认成功的发送不重发；发送后、确认落盘前崩溃仍可能重复投递。
- 端口占用时通过实际绑定尝试后续端口，保留原占用进程；资料库记录选中的地址，启动器核对资料库身份。Mac、Ubuntu 隔离实例都实测换端口、重复打开复用、停止后重新启动沿用端口。
- Tailscale 仅在已有根路由指向本项目旧端口且当前用户有权限时同步；不使用 sudo、重置其他路由或开启 Funnel。权限不足时输出明确修复命令入口。该分支通过模拟配置与权限失败验证，未切换原服务器的 443 转发。

Mac 新 HOME 安装、首次使用引导与模拟采集到 PNG 工作流已通过。Ubuntu 隔离源码回归与真实端口恢复已通过；环境检查中发现并补齐隔离测试所需的 Node 路径和 npm 锁定依赖。

## 证据边界

本轮首次使用页面与采集出图采用虚构账号/消息，验证安装和工作流，不冒充新的 Discord 账号登录验收；未要求用户重复扫码，也没有提取浏览器 Cookie。已有真实账号验收见原验收记录。Mac 的人机验证是否通过仍由 Discord 决定。Windows 客户端和第二台实体 Mac 未在本轮新增实机验收。

应用退出期间不能执行任务；自动补跑的前提是应用再次运行、账号与网络可用，且自动任务未暂停。图片存档的长期容量管理不等同于推送记录整理，本轮没有删除旧图片以腾空间。
