# 常见问题

Mac 安装问题按下表处理；Linux 的 SSH、私网、隧道和服务问题见 [Linux 常见访问问题](LINUX.md#4-常见访问问题)。

| 情况 | 先做什么 | 如何确认或继续处理 |
| --- | --- | --- |
| 安装或浏览器下载失败 | 保留终端最后的错误提示，检查网络后重新双击 Install.command | 等到“安装检查通过”；重新安装不会删除已有归档 |
| 工作台没有自动打开 | 在这台 Mac 的浏览器打开 [本地工作台](http://127.0.0.1:8765) | 仍打不开时，重新双击 Start.command，保留终端报错 |
| 需要重新检查环境 | 在项目目录执行 `./Install.command --check` | 根据输出处理缺失组件；检查不读取聊天或凭证 |
| Mac 本地登录窗口打不开 | 重新运行 Install.command 检查浏览器环境，再点“连接 Discord” | 不需要浏览器扩展；保留原连接和资料 |
| Ubuntu 首次连接工具缺失 | 使用对应访问电脑的连接包，并按 Linux 首次连接步骤操作 | 仅 Ubuntu 绑定用扩展；已有连接时换电脑不重复 |
| 无法连接 Discord 或保存失败 | 先确认日常浏览器能正常登录 Discord，再到“我的稿件 → 保存记录”看失败说明 | 认证失效时重新连接；权限失败时确认当前账号还能查看该频道 |
| 普通浏览器的 HTTPS 连接被关闭 | 双击访问客户端，由专用窗口直连工作台 | 不必修改系统代理；确认 Tailscale 在线、服务器 Serve 与应用运行；TUN / 企业强制代理另行诊断 |
| 账号连接失效或首次未连接 | Mac 按 [本机登录](MAC.md#登录-discord)；Ubuntu 按 [扩展绑定](LINUX_SETUP.md#连接-discord)，已有资料保留 | 看到“连接成功”并用一个小频道验证；日常访问不重复绑定 |
| HTTPS 返回无权访问 | 核对客户端 Tailscale 登录身份是否是服务器配置的所有者 | 管理员在服务器检查 `data/remote-access.json`；不要改成接受任意身份头 |
| 语音安装失败或稿件没有转写 | 核对平台、FFmpeg、模型安装结果，以及目标发言人与稿件日期 | 模型应安装在实际运行应用的机器；修好后生成新稿件，不只重新打开旧稿件 |
| 使用代理，浏览器正常但保存失败 | 检查代理是否覆盖后台程序的连接，而不仅是浏览器；保留保存记录中的网络错误 | 当前 README 未提供适用于所有代理软件的配置步骤；求助时注明代理软件名称和启动方式，不要提供订阅链接或密钥 |
| 保存成功，但没有预期的答疑内容 | 核对频道、答疑人的消息链接和“调整”中的整理范围 | 目标发言需在已保存内容中；后续“最近一轮”可能没有新增发言，可改用“整个交易日”核对 |
| 文字稿有了，图片没生成 | 在稿件列表的对应条目旁点“生成图片”，查看是否有错误 | 环境检查失败时重跑安装；内容过大时缩小整理日期范围后再生成 |
| 定时出稿没有按时产生文件 | 检查“下次出稿”“最近状态”和页面错误，并确认服务所在电脑当时未睡眠 | 核对纽约时间、启用开关、服务是否运行及自动另存目录是否可用 |

Mac 工作台仍未就绪时，在 Finder 打开项目中的 `data` 文件夹，查看 `launcher.log` 或 `service.log`。Linux 使用 [服务状态与日志命令](LINUX.md#5-日常管理与验收)。只提供与本次失败有关的错误片段。

**向别人求助时：**说明卡在哪一步、操作系统与芯片类型，以及当时的错误文字或截图。先遮住账号、频道、聊天内容和个人文件路径；不要发送密码、验证码、凭证、完整日志或整个 `data/` 文件夹。
