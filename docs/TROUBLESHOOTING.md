# 常见问题

先确认正在使用 Mac、Docker 还是原生 Ubuntu，再按下表处理。服务启动命令见 [日常管理](OPERATIONS.md#以后如何打开)。

| 情况 | 先做什么 | 如何确认或继续处理 |
| --- | --- | --- |
| 安装或浏览器下载失败 | 保留终端最后的错误提示，检查网络后重新双击 Install.command | 等到“安装检查通过”；重新安装不会删除已有归档 |
| Mac 工作台没有打开 | 双击 Start.command，使用它输出的实际地址 | 默认 8765 可能已换端口；仍失败时保留终端报错 |
| 需要重新检查环境 | 在项目目录执行 `./Install.command --check` | 根据输出处理缺失组件；检查不读取聊天或凭证 |
| Mac 原生版误跳登录助手，或旧助手报 AppTranslocation 路径不存在 | 更新到 v0.1.1 并只重启本应用，再点“连接 Discord”；原生版不需要助手或扩展 | 不用重装依赖、删除资料或关闭系统保护；连接 Docker/远端时使用新版 `.command` 助手入口 |
| Mac 本地登录窗口打不开 | 重新运行 Install.command 检查浏览器环境，再点“连接 Discord” | 不需要浏览器扩展；保留原连接和资料 |
| Mac 扫码登录卡在人机验证 | 改用账号和密码登录，按页面提示完成验证 | 作者多次扫码遇到此问题；账号密码登录也可能需要验证，不保证免验证 |
| Ubuntu 首次连接工具缺失 | 按 [首次连接](LOGIN_ASSISTANT.md#首次连接-discord)取得对应客户端 | Mac 用 arm64，Windows 用 x64；已有连接不重绑 |
| Docker 工作台打不开 | 在部署目录执行 `sudo bash Start-Docker.sh`，再检查 Tailscale | 用 HTTPS 地址；日志：`sudo docker compose logs --tail 80` |
| 无法连接 Discord 或保存失败 | 先确认日常浏览器能正常登录 Discord，再到“我的稿件 → 保存记录”看失败说明 | 认证失效时重新连接；权限失败时确认当前账号还能查看该频道 |
| 普通浏览器的 HTTPS 连接被关闭 | 双击访问客户端，由专用窗口直连工作台 | 不必修改系统代理；确认 Tailscale 在线、服务器 Serve 与应用运行；TUN / 企业强制代理另行诊断 |
| 账号连接失效或首次未连接 | Mac 按 [本机登录](MAC.md#登录-discord)；Ubuntu 按 [扩展绑定](LOGIN_ASSISTANT.md#首次连接-discord)，已有资料保留 | 看到“连接成功”并用一个小频道验证；日常访问不重复绑定 |
| HTTPS 返回无权访问 | 核对客户端 Tailscale 登录身份是否是服务器配置的所有者 | 管理员在服务器检查 `data/remote-access.json`；不要改成接受任意身份头 |
| 语音安装失败或稿件没有转写 | 核对平台、FFmpeg、模型安装结果，以及目标发言人与稿件日期 | 模型应安装在实际运行应用的机器；修好后生成新稿件，不只重新打开旧稿件 |
| 使用代理，浏览器正常但保存失败 | 检查代理是否覆盖后台程序的连接，而不仅是浏览器；保留保存记录中的网络错误 | 求助时注明代理软件和后台启动方式，不提供订阅链接或密钥 |
| 保存成功，但没有预期的答疑内容 | 核对频道、答疑人的消息链接和“调整”中的整理范围 | 目标发言需在已保存内容中；后续“最近一轮”可能没有新增发言，可改用“整个交易日”核对 |
| 文字稿有了，图片没生成 | 在稿件列表的对应条目旁点“生成图片”，查看是否有错误 | 环境检查失败时重跑安装；内容过大时缩小整理日期范围后再生成 |
| 定时出稿没有按时产生文件 | 检查“下次出稿”“最近状态”，以及是否暂停自动任务 | 核对纽约时间、执行日、服务是否运行；已配置目录时再检查目录权限。配置推送不能代替启用定时出稿 |

## 图片推送问题

先看 **高级设置 → 自动推送** 下的发送记录，再看目标邮箱或聊天。不要反复点击测试按钮；每次点击都会新建一次测试任务。

| 情况 | 先检查 | 处理与成功标志 |
| --- | --- | --- |
| 设置里没有“自动推送”或没有 ClawBot | 正在访问的是 Mac 还是 Ubuntu？服务端是否用了新源码？ | 按 [已有安装更新](DELIVERY.md#已有安装如何更新)补齐代码和依赖、重启服务，再刷新网页；只更新客户端不会更新服务器 |
| 测试成功，但每天不发图 | 渠道开关、定时出稿开关、两处保存按钮，以及“自动任务已暂停” | 按 [自动收图步骤](DELIVERY.md#从测试到每天自动收图)逐项核对；第一次真实定时执行后确认长图收到 |
| 一直“等待发送” | 是否有采集、生成图片等任务尚未结束？ | 任务串行处理，先等已开始任务完成；主动测试不受自动任务暂停影响。服务停了则先启动 |
| 显示“等待重试”或“发送失败” | 记录里的具体错误、服务器出站网络、凭据、目标地址和文件大小 | 修好后等待重试或点“重试发送”；超限旧图不会因重试变小，需重新生成较小图片 |
| 邮件“已发送”，收件箱没有 | 收件地址、垃圾邮件、发件服务的退信和收件方限制 | “已发送”只是 SMTP 接受提交。确认真实收件，首次先用一个收件地址排查 |
| 邮箱认证失败 | SMTP 是否开启、登录名、授权码、端口与加密是否配套 | 按服务商要求生成 SMTP 凭据；当前不支持 OAuth，账号不允许密码认证时需换支持的服务 |
| Telegram 没有 Chat ID，或测试被拒绝 | 是否对正确 Bot 发了 `/start`？ID 是否属于这个 Bot 收到的私聊？ | 按 [取得 Chat ID](DELIVERY.md#2-取得-chat-id)操作，核对目标后保存测试；群和频道还需检查 Bot 权限 |
| Discord 没收到 | Webhook 是否指向预期频道、是否仍有效？ | 先用“保存并测试Discord”确认目标；地址须为官方 Webhook URL。不要把账号登录凭证填进 Webhook 框 |
| ClawBot 二维码过期或旧对话找不到 | 手机“我 → 设置 → 插件 → 微信 ClawBot”入口，以及当前二维码状态 | 在应用重新生成二维码，用 ClawBot 的“开始扫一扫”扫新码并确认；不要重复扫过期截图 |
| ClawBot 已绑定但提示发消息 | 是否在手机微信中向 ClawBot 主动发过消息？ | 发一句“你好”，等待“微信会话可发送”，再测试；在此处聊天回复不等于给微信 ClawBot 发消息 |
| ClawBot 显示“需微信操作” | 是否提示会话不可用、登录失效或绑定对象改变？ | 会话问题先在微信发消息；登录失效重新扫码；换账号后确认收件人，再手动重试旧记录 |
| ClawBot 二维码或加密组件不可用 | 新版依赖是否安装在服务器？Node.js 是否可用？ | 原生版重跑安装器；Docker 按新版镜像更新。无需安装 OpenClaw |
| 保存了新凭据却仍不生效 | 服务是否通过环境变量提供了同类凭据？ | 环境变量优先于页面值，需修改实际服务的环境并安全重启。不要把环境文件发给别人排查 |
| 多张图片只看到一条，或收到重复邮件 | 平台是否把邮件合并成会话？是否多次点测试或发生确认丢失？ | 展开每条消息核对页码；成功文件一般不会因其他文件失败重发，但网络确认丢失时可能重复 |

测试 PNG 很小，只用于验证连接；它不是实际稿件长图。普通手动出图不会自动发送，首次完整验收要观察一次定时出图、发送和实际收件。[详细配置与限制](DELIVERY.md)

Mac 工作台仍未就绪时，在 Finder 打开项目中的 `data` 文件夹，查看 `launcher.log` 或 `service.log`。Docker 使用本页日志命令；原生 Linux 见 [服务日志](LINUX.md#5-日常管理与验收)。只提供与本次失败有关的错误片段。

**向别人求助时：**说明卡在哪一步、操作系统与芯片类型，以及当时的错误文字或截图。先遮住账号、频道、聊天内容和个人文件路径；不要发送密码、验证码、凭证、完整日志或整个 `data/` 文件夹。
