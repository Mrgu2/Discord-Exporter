# 使用教程

先完成 [Mac 本地安装](MAC.md) 或 [Ubuntu 首次部署](LINUX_SETUP.md)，再按下面步骤操作。

## 第一次采集出图

以下步骤在已经打开的工作台中操作，Mac 和 Linux 共用。第一次先选一个频道完成出稿，再添加更多频道。

### 1. 确认连接与测试范围

确认 Mac 已按 [本机登录](MAC.md#登录-discord)完成连接，或 Ubuntu 已具备有效账号连接（[配置边界](LINUX_SETUP.md#连接-discord)）；在对应工作台看到“添加频道与答疑人”后继续。

先在 **高级设置 → 服务控制**选择“**暂停自动任务**”，再配置频道；首次部署建议保持暂停。暂停不影响手动保存、出稿和出图，避免首次配置后默认自动保存提前开始。

**只选一个历史消息与附件都少的频道。** 首次“保存一次”会读取这个频道全部仍可见的历史；“整个交易日 / 自选日期”只限制稿件范围，不限制采集量。当前工作台没有“只采 25 条”的开关，不能把验收脚本的限量取样当作产品功能。拿不准频道体量时，先不勾选大讨论频道。

### 2. 添加一个频道和答疑人

1. 按工作台提示点击 **添加频道与答疑人**，进入“频道与发言人”设置。
2. 在 Discord 中找到要保存的频道，右键其中一条消息，选“**复制消息链接**”。粘贴到“**频道 ID 或消息链接**”中。第一次先填一个频道；以后可每行填一个频道链接。
3. 找到你要整理的答疑人发过的一条消息，同样复制消息链接，粘贴到“**答疑人的一条消息链接**”。不需要自己查用户 ID。
4. 点击 **保存并返回工作台**。若是在“高级设置”中日常修改，则点击 **保存设置**，再回到工作台。

**检查：**“保存哪些频道”中应出现刚添加的频道，并勾选它。频道链接用于指定“保存哪里”，答疑人的消息链接用于指定“围绕谁整理”，两项都需要配置。

### 3. 保存消息并生成稿件

1. 点击 **保存一次**，等待正在处理的提示结束，并确认“**上次保存**”已更新。打开“**我的稿件 → 保存记录**”，确认这一轮保存成功；若显示失败或部分失败，先查看说明。
2. 点击左侧 **工作台** 返回；“生成稿件”按钮位于工作台，不在保存记录页。
3. 展开 **调整**，首次建议选择“**整个交易日**”，并在“**交易日期**”中选择一个你确认该答疑人发过消息的日期。这里按纽约时间凌晨 4 点划分交易日，不一定等于你电脑显示的自然日。
4. 点击 **生成稿件**，等待结果出现在“**最近稿件**”中。若提示所选范围没有目标发言，重新核对答疑人和交易日期。
5. 点击对应稿件的标题或 **打开 ↗**，查看文字是否包含预期的答疑内容。

**首次保存可能较久：**程序会读取该频道中仍可见的历史消息，耗时取决于内容量和网络。处理中先等待，不要反复启动程序。已经从 Discord 删除且从未保存的消息无法补回。

不调整时，默认整理范围是“最近一轮”：首次包含全部已保存的目标发言，后续主要选取相对上次成功保存新增或编辑的目标发言。需要整天或某段日期的内容时，展开工作台的 **调整**，选择“整个交易日”或“自选日期”；交易日按纽约时间凌晨 4 点分界。

### 4. 生成并下载第一张图片

1. 回到工作台，在“**最近稿件**”的对应条目旁点击 **生成图片**。首次可保持默认的“标准 · 1×”。
2. 等待图片生成完成，点击 **查看长图** 检查内容，再点击 **下载图片**。如果结果有多张，条目会显示“下载第 1 张”，其余图片可在长图预览中切换并下载。
3. 在浏览器的下载列表中找到 PNG，打开确认文字可读、内容符合预期。浏览器下载位置由浏览器设置决定。

**做到这里才算首次使用跑通：**保存记录成功、稿件有预期内容、下载的 PNG 能正常打开。只看到工作台或账号已连接，还不能证明保存和出图成功。

## 语音转写（可选）

**在哪运行应用，就在哪里安装语音。** 访问客户端不处理账号或模型；只用 Linux 采集时，不必给客户端安装语音模型。

| 平台 | 在哪里操作 | 安装入口与默认配置 | 成功标志 |
| --- | --- | --- | --- |
| Apple Silicon Mac | Mac 的项目文件夹 | 双击 **Install-Speech.command**；MLX Medium 多语言模型 | “语音环境与模型检查通过”并最终显示“安装检查通过” |
| Ubuntu / Linux | 服务器 SSH 终端，先 `cd` 到服务器项目目录 | `python3 scripts/install_speech.py`；small 多语言模型、CPU / INT8 | “语音环境和模型已实际加载” |
| Intel Mac | 基础功能照常使用 | 当前语音安装入口不支持；需要语音时可部署到 Linux | 不将语音安装失败视为基础安装失败 |

安装需要联网下载环境与模型，并预留数 GiB 空间（尤其 Mac Medium）；转写在应用所在机器上读取本地模型和已保存音频。Mac 缺 FFmpeg 时，安装入口通过 Homebrew 按需安装。Linux 基础安装已准备 FFmpeg 和 Python venv。

Linux 模型位于 `.runtime/models/faster-whisper-small`，隔离环境位于 `.venv/whisper-linux`。默认不需要独立 GPU；NVIDIA CUDA 为可选配置，AMD 为后续适配方案，详见 [模型切换与 GPU 说明](LINUX.md#3-语音转写默认-small--cpu)，不要把这些选项当成已完成 GPU 实机验收。

安装成功后**不用重启服务**：下一次“保存一次”或“生成稿件”会读取新配置，已开始的任务先等它结束，旧稿件不会自动更新。

### 如何确认语音真的能用

1. 先确认已保存的目标发言中确实有语音。若需要新采集，只选已知的小频道；不要为测试语音勾选整个大讨论频道。
2. 在工作台“调整”中选择这条语音所在的交易日或日期范围，点 **生成稿件**。语音应由指定答疑人发送；别人的语音未必被选进稿件。交易日按纽约时间凌晨 4 点分界。
3. 打开新稿件，确认出现“**语音转写**”，对照原音频核对内容，再点 **生成图片**、下载 PNG，确认转写文字也进入图片。
4. 若显示待转写或错误，按原因处理环境、模型或音频，再重新生成稿件；安装检查通过不等于实际语音已经转写成功。

未安装语音时仍保存原音频，基础文字和长图可用。转写是派生文字，尤其数字与交易术语需要回听核对。

已在 Ubuntu small / CPU 上完成真实短语音样本的下载、转写、缓存、文字稿、横版和手机版出图；另有小频道真实采集验收。范围与未验证项见 [Linux 验收记录](LINUX_ACCEPTANCE.md)。限量样本通过不代表工作台支持限量采集，也不代表所有长语音或账号均已验收。
