# 使用教程

先完成 [Mac 安装](MAC.md)、[Ubuntu Docker 安装](DOCKER.md) 或 [Windows Docker 安装](WINDOWS_DOCKER.md)；Ubuntu 原生版见 [替代安装教程](LINUX_SETUP.md)。

## 第一次采集出图

Mac、Ubuntu 和 Windows Docker 使用同一工作台。

### 1. 确认连接与测试范围

工作台应显示 **添加频道与答疑人** 或已连接账号。未连接时，按 [Mac 登录](MAC.md#登录-discord)或 [Docker / Ubuntu 首次连接](LOGIN_ASSISTANT.md#首次连接-discord)完成。

先在 **高级设置 → 服务控制**点击 **暂停自动任务**。暂停不影响手动保存和出图。

**只选一个消息、附件都少的频道。首次保存读取全部可见历史，稿件日期不限制采集量。** 工作台没有限量采集开关。

### 2. 添加一个频道和答疑人

1. 点击 **添加频道与答疑人**。
2. 在 Discord 复制该频道任意一条消息的链接，填入 **频道 ID 或消息链接**。
3. 复制答疑人发过的一条消息链接，填入 **答疑人的一条消息链接**，无需查用户 ID。
4. 点击 **保存并返回工作台**，确认新频道已勾选。

频道决定“保存哪里”，答疑人决定“围绕谁整理”，两项都要填。以后可每行添加一个频道链接。

### 3. 跟随首次出图提示

依次点击：

1. **确认保存所选频道**：核对采集范围，等待保存完成。
2. **生成首份稿件**：默认用“最近一轮”和“本地证据稿”。没有目标发言时，先检查答疑人和保存结果。
3. **生成第一张图片**：生成标准 1× 主图。
4. **查看图片 / 下载图片**：核对内容，下载 PNG 并打开。首次下载入口对应第 1 张，其余页在预览中切换。

**完成标准：保存成功、稿件有预期内容、PNG 能打开且文字可读。** 已有图片的资料库不再显示首次引导，按下面的常规操作继续。

### 下一步

第一张 PNG 下载并打开后，首次使用已完成：

- **[以后如何打开工作台](OPERATIONS.md#以后如何打开)**：启动、停止与自动运行。
- **[设置定时图片推送](DELIVERY.md)**（可选）：先测试收件，再开启定时任务。
- **[启用或检查语音转写](#语音转写可选)**（可选）。

继续手动使用时，看下面的常规操作，无需重新安装或绑定。

### 4. 常规保存与稿件选项

在工作台依次点 **保存一次 → 生成稿件**，结果出现在“最近稿件”。保存失败时，先看 **我的稿件 → 保存记录** 的错误。

展开 **调整**可修改范围：

| 范围 | 整理什么 |
| --- | --- |
| 最近一轮（默认） | 首轮包含已保存的目标发言；后续选取相对上次成功保存新增或编辑的目标发言 |
| 整个交易日 | 所选纽约交易日，按凌晨 4 点分界 |
| 自选日期 | 所选日期范围内的内容 |

找不到预期内容时，核对频道、答疑人及日期；交易日可能不同于电脑显示的自然日。处理中等待完成，无需重复启动程序。已删除且从未保存的消息无法补回。

### 5. 常规图片生成与下载

在对应稿件旁选择 **标准 · 1×** 或 **HiDPI · 2×**，点击 **生成图片**。完成后点 **查看长图**，核对内容并下载；多页在预览中切换下载。PNG 保存到浏览器设置的下载目录。

## 每天自动出图并收取（可选）

先手动生成一张图片，再按 [推送教程](DELIVERY.md)配置渠道、测试收件并开启定时出稿。手动出图不会自动发送。

Mac 的本地工作台与 Ubuntu 的 HTTPS 工作台各自保存配置。用 Ubuntu 出图，就在 Ubuntu 工作台配置推送。自动保存、定时出稿和自启动的区别见 [日常管理](OPERATIONS.md#自动功能与推送有什么区别)。

## 语音转写（可选）

在运行应用的机器上配置，访问电脑无需安装模型。

| 运行方式 | 安装与默认模型 | 成功标志 |
| --- | --- | --- |
| Apple Silicon Mac | 双击 **Install-Speech.command**；MLX Medium 多语言模型 | “语音环境与模型检查通过”，随后“安装检查通过” |
| Ubuntu Docker | 镜像已含 small，多语言 / CPU INT8 | 安装时显示“语音环境和 small 模型已实际加载” |
| Ubuntu 原生 | 在项目目录执行 `python3 scripts/install_speech.py`；small / CPU INT8 | “语音环境和模型已实际加载” |
| Intel Mac | 当前语音安装入口不支持；可改用 Ubuntu 处理 | 基础采集和出图仍可用 |

Mac 和原生 Ubuntu 首次安装需联网并预留数 GiB 空间。Docker 的模型在 `models` 卷；原生 Ubuntu 在 `.runtime/models/faster-whisper-small`，环境在 `.venv/whisper-linux`。[模型切换与 GPU 配置](LINUX.md#3-语音转写默认-small--cpu)用于原生版；Docker GPU 需另行适配，尚未实测。

配置生效后无需重启，下一次保存或出稿会读取新设置；旧稿件不自动更新。未启用语音时仍保存原音频。

### 如何确认语音真的能用

1. 选一条已保存的、由目标答疑人发送的语音，按它的日期生成新稿件。
2. 确认稿件出现 **语音转写**，回听核对数字和术语。
3. 生成并下载 PNG，确认转写文字也在图片中。待转写或失败时，按错误修正模型、环境或音频后重新出稿。

实测范围见 [Docker 验收](DOCKER_ACCEPTANCE.md)；原生版验证方法见 [Linux 验收](LINUX_ACCEPTANCE.md)。
